# 核心用户表与数据库基线

本文档覆盖数据库基础集成分支的 V1-V6，依据仓库现有实体、Mapper、业务服务以及接口设计文档总册整理。B 负责的 V4-V5 已合并进集成分支，文件与任务表细节见 `02_文件与任务表.md`。

## 1. 迁移边界

| 版本 | 文件 | 内容 | 状态 |
| --- | --- | --- | --- |
| V1 | `V1__baseline_existing_tables.sql` | 接入 Flyway 前已有的十张表 | 本分支完成 |
| V2 | `V2__user_profile_and_goal.sql` | 用户画像、备考目标 | 本分支完成 |
| V3 | `V3__idempotency_and_audit.sql` | 幂等记录、登录日志、操作审计 | 本分支完成 |
| V4-V5 | `V4__file_storage.sql`、`V5__async_task_and_outbox.sql` | 文件、上传会话、异步任务与 Outbox | B 已完成并合并 |
| V6 | `V6__seed_rbac_dictionary.sql` | 角色、权限及关系字典 | 本分支完成 |

迁移文件一经合并到 `feat/db-foundation` 就不得修改，只能新增版本。项目唯一建表入口为 `backend/src/main/resources/db/migration`，旧的 `db/schema.sql` 已删除。

## 2. 全局约定

| 项目 | 约定 |
| --- | --- |
| 主键 | `BIGINT NOT NULL AUTO_INCREMENT` |
| 表名、字段名 | 小写蛇形命名 |
| 时间 | `DATETIME`；账号审计时间使用应用时区 `Asia/Shanghai` |
| 分数 | `DECIMAL`，禁止 `FLOAT/DOUBLE`；目标总分为 `DECIMAL(6,2)`，为后续 500 分制保留余量 |
| 枚举 | SQL 注释中的编码与 Java、接口文档保持一致 |
| 逻辑删除 | `TINYINT`，0 正常，1 删除 |
| 环境配置 | 仓库只保留 `deploy/.env.example`，实际值写入被忽略的 `deploy/.env` |

V1 沿用已有字段，不引入物理外键，避免存量库升级和跨模块删除顺序耦合。归属校验由服务层完成，角色权限关系使用唯一键防重。

## 3. V1 历史表

### 3.1 `sys_user`

账号主表，密码字段只保存 BCrypt 哈希。

| 字段 | 类型 | 空/默认 | 键与索引 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 非空，自增 | PK | 用户主键 |
| `username` | `VARCHAR(64)` | 非空 | 唯一索引 `username` | 当前实现的登录账号，业务唯一 |
| `password_hash` | `VARCHAR(128)` | 非空 | - | BCrypt 哈希，不保存明文 |
| `nickname` | `VARCHAR(64)` | 可空 | - | 昵称 |
| `email` | `VARCHAR(128)` | 可空 | - | 邮箱 |
| `avatar` | `VARCHAR(255)` | 可空 | - | 头像 URL，接口别名 `avatar_url` |
| `status` | `TINYINT` | 非空，默认 1 | - | 0 禁用，1 正常 |
| `create_time` | `DATETIME` | 非空，当前时间 | - | 账号创建时间 |
| `update_time` | `DATETIME` | 非空，自动更新 | - | 最近修改时间 |

### 3.2 RBAC 表

| 表 | 作用 | 关键约束 | 主要写入模块 |
| --- | --- | --- | --- |
| `sys_role` | 角色字典 | `role_code` 唯一 | Flyway V6 |
| `sys_permission` | 权限字典 | `perm_code` 唯一 | Flyway V6 |
| `sys_user_role` | 用户与角色关系 | `uk_user_role(user_id, role_id)` | `AuthService`、`AdminService` |
| `sys_role_permission` | 角色与权限关系 | `uk_role_perm(role_id, permission_id)` | Flyway V6；管理员可在后台调整 |

RBAC 字典的唯一写入来源是 Flyway V6。`RbacInitializer` 只校验必填权限、四个内置角色和默认绑定是否齐全，不再插入或覆盖任何数据；校验失败时应用会终止启动，避免带病运行。

### 3.3 知识与会话表

| 表 | 主键/业务唯一键 | 读取或写入模块 | 关键说明 |
| --- | --- | --- | --- |
| `kb_knowledge_base` | PK `id` | `KnowledgeService`、`RetrievalService` | `visibility` 区分私有/公开；`user_id` 为归属 |
| `kb_document` | PK `id` | `KnowledgeService`、文档处理流水线 | 原文存 `raw_text`，对象存 MinIO，`status` 表示解析阶段 |
| `kb_document_chunk` | PK `id` | 文档处理与检索 | `milvus_id` 与业务切片对应；当前由服务层维护切片序号 |
| `chat_conversation` | PK `id` | `ChatService` | 按 `user_id + deleted` 查询；`idx_conv_user(user_id)` 支撑用户过滤 |
| `chat_message` | PK `id` | `ChatService` | 按 `conversation_id` 顺序读写；引用信息以 JSON 文本保存 |

## 4. V2 用户画像与备考目标

### 4.1 `user_profile`

一个用户只有一条稳定画像记录。

| 字段 | 类型 | 空/默认 | 键与索引 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 非空，自增 | PK | 主键 |
| `user_id` | `BIGINT` | 非空 | `uk_user_profile_user` | 用户主键 |
| `gender` | `TINYINT` | 可空 | - | 0 未知，1 男，2 女 |
| `major` | `VARCHAR(100)` | 可空 | - | 本科专业 |
| `grade` | `VARCHAR(32)` | 可空 | - | 年级或备考阶段 |
| `base_level` | `TINYINT` | 可空 | - | 1 薄弱，2 一般，3 良好，4 扎实 |
| `weekly_study_minutes` | `INT` | 非空，默认 0 | - | 每周学习分钟数 |
| `weak_points_json` | `JSON` | 可空 | - | 薄弱知识点数组 |
| `profile_json` | `JSON` | 可空 | - | 扩展画像；可含科目掌握度、时长分布等 |
| `create_time` | `DATETIME` | 非空 | - | 由写入模块设置 |
| `update_time` | `DATETIME` | 非空 | - | 由写入模块设置 |

`profile_json` 用于保存可变结构，接口可直接返回；经常筛选或聚合的字段必须提升为独立列，不能只藏在 JSON 中。

### 4.2 `user_study_goal`

目标按考试年度变化，同一用户同一年度只有一条记录。

| 字段 | 类型 | 空/默认 | 键与索引 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 非空，自增 | PK，接口别名 `goal_id` | 主键 |
| `user_id` | `BIGINT` | 非空 | `uk_goal_user_year`、`idx_goal_user_status` | 用户主键 |
| `target_school_id` | `BIGINT` | 可空 | - | 目标院校主键 |
| `target_school_name` | `VARCHAR(100)` | 可空 | - | 目标院校名称快照 |
| `target_major` | `VARCHAR(100)` | 可空 | - | 目标专业 |
| `target_score` | `DECIMAL(6,2)` | 可空 | - | 目标总分 |
| `target_subject_scores` | `JSON` | 可空 | - | 单科目标分键值对 |
| `exam_year` | `INT` | 非空 | `uk_goal_user_year` | 考试年度 |
| `exam_date` | `DATE` | 可空 | - | 初试日期 |
| `plan_type` | `TINYINT` | 非空，默认 1 | - | 1 按日，2 按周，3 按月 |
| `status` | `TINYINT` | 非空，默认 1 | `idx_goal_user_status` | 0 未启动，1 进行中，2 已完成，3 已放弃 |
| `remark` | `VARCHAR(500)` | 可空 | - | 备注 |
| `deleted` | `TINYINT` | 非空，默认 0 | - | 0 正常，1 逻辑删除 |
| `version` | `INT` | 非空，默认 0 | - | 乐观锁版本 |
| `create_time` | `DATETIME` | 非空 | - | 由写入模块设置 |
| `update_time` | `DATETIME` | 非空 | - | 由写入模块设置 |

画像表不得重复保存 `target_score`、院校和年度目标。接口中的 `target_major`、`exam_year` 等字段需要通过当前用户最新一期备考目标组合计算。

## 6. V6 RBAC 字典

| 角色 | 权限 |
| --- | --- |
| `SYSTEM_ADMIN` | 全部 11 条权限 |
| `STUDENT` | `chat:send` |
| `CONTENT_OPERATOR` | `kb:view`、`kb:create`、`kb:delete`、`doc:upload`、`doc:delete`、`admin:vector:manage` |
| `DATA_AUDITOR` | `kb:view`、`admin:user:list`、`admin:role:list` |

V6 不预置管理员账号。空库首次注册时，`AuthService` 看到 `SYSTEM_ADMIN` 下没有用户，会把首个注册者绑定为系统管理员。已有库若仍使用旧 `ADMIN` 角色，V6 会先迁移用户角色和自定义角色权限，再删除旧角色，避免升级后管理员失权。

## 7. 与接口文档的已知差异

以下差异必须在实现用户中心接口时处理，不能把文档字段误标为已经完成：

| 项目 | 接口设计文档 | 仓库当前实现 | 处理原则 |
| --- | --- | --- | --- |
| 登录标识 | 手机号 `phone` | `sys_user.username` | V1 保持现有字段；后续若要支持手机号，新增迁移并补唯一索引，不在已合并基线中改字段 |
| 接口前缀 | `/api/v1/...` | `/api/...` | 接口负责人统一迁移，不在 A 的数据库分支修改 Controller |
| 登录态 | JWT + refresh token | Sa-Token | 不新增 Token 表；安全要求是不落库 Token |
| 角色编码 | `STUDENT/CONTENT_OPERATOR/DATA_AUDITOR/SYSTEM_ADMIN` | V6 与 Java 常量已对齐 | 后续新增角色必须同时更新 Flyway 种子常量与启动校验 |
| 画像/目标接口 | 文档已定义 GET/PUT/PATCH | 当前仅基础用户资料接口 | A 只交付表结构和字段映射，不越界开发用户中心业务接口 |

## 8. 本地验证

```powershell
cd backend
mvn test
mvn -DskipTests package
```

空库启动时检查：

```sql
SELECT installed_rank, version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;

SHOW TABLES;
```

已有数据库第一次升级时，Flyway 会以版本 0 建立基线，再执行 V1-V6；第二次启动只做 Flyway 与 RBAC 校验，不应重复创建表或写入记录。
