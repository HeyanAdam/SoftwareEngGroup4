# 文件存储 ABCD 协作顺序

> 适用对象：A 后端负责人、B 上传引擎负责人、C 登录态负责人、D 集成负责人
> 协作方式：群内同步接口，GitHub 功能分支开发，D 统一合并和验收

## 1. 总体分工

```text
D：建立集成分支、页面、业务入口、最终合并和验收
A：文件后端、数据库、MinIO、分片合并、下载和安全校验
C：登录页面、Token、Axios、401 和路由守卫
B：前端上传接口、分片、重试、暂停续传和上传任务中心
```

一句话概括：

```text
D 建分支和收尾，A 管后端，C 管登录态，B 管上传，D 管页面。
```

## 2. 最简单的 GitHub 分支

由 D 建立集成分支：

```text
main
└── file-storage
```

其他成员分别建立功能分支：

```text
A：file-backend
B：file-upload
C：auth-frontend
D：file-ui
```

四个功能分支先合并到：

```text
file-storage
```

最终由 D 将：

```text
file-storage -> main
```

## 3. 开工前在群里固定接口

D 在群里发一次固定约定即可：

```text
文件接口统一使用 /api/v1/files
请求头统一使用 Authorization: Bearer <token>
临时 Token 存储在 kaoyan_access_token
功能先合到 file-storage
最终由 D 合并到 main
```

接口变更由对应负责人发到群里，并同步更新文档和调用代码。

## 4. 第一阶段：四个人同时开工

### 4.1 A 开始后端

A 优先完成：

1. 启动 MinIO。
2. 跑通小文件上传。
3. 返回真实 `fileId`。
4. 跑通文件列表。
5. 向 B 和 D 提供接口示例。

A 先交付：

```http
POST /api/v1/files
GET  /api/v1/files
```

### 4.2 C 开始登录态

C 先完成最小登录能力：

1. 登录取得 Token。
2. Token 保存到浏览器。
3. Axios 自动添加请求头。
4. 401 清理 Token。
5. 提供真实测试账号的 Token 获取方式。

C 尽快在群里发：

```text
Token 存储键
登录接口
请求头格式
测试账号获取方式
```

完整登录页面继续由 C 完成。

### 4.3 B 开始上传引擎

B 先使用 Mock 数据开发：

1. 封装文件 API。
2. 完成小文件上传。
3. 完成批量上传。
4. 搭好上传任务中心。
5. 准备分片上传数据结构。

B 在 A 的小文件接口跑通后，将 Mock 切换到真实接口。

### 4.4 D 开始页面

D 先使用 Mock 数据开发：

1. 文件列表。
2. 场景筛选。
3. 分页。
4. 上传按钮。
5. 下载和删除按钮。
6. 全局上传任务中心的位置。

D 在 A 和 B 的接口跑通后逐步替换 Mock。

## 5. 第二阶段：先跑通小文件

第一轮按以下链路配合：

```text
A 小文件接口
    ↓
B 小文件上传
    ↓
D 文件列表
```

### 5.1 A 对 B 的交接

A 在群里提供：

```text
接口路径
请求字段
成功响应
错误响应
一个真实 fileId
一个真实 Token 获取方法
```

B 收到后完成真实上传调用。

### 5.2 B 对 D 的交接

B 向 D 提供：

```vue
<UploadTaskCenter
  :files="files"
  :scene="scene"
  @completed="handleCompleted"
  @failed="handleFailed"
/>
```

B 同时说明：

```text
files：选择的文件
scene：文件场景
completed：上传成功事件
failed：上传失败事件
```

D 只负责接入组件和处理结果，上传状态机由 B 维护。

### 5.3 D 对 A 和 B 的反馈

D 在页面接入时记录：

```text
缺少的字段
响应不匹配的位置
页面需要的操作
下载和删除接口
```

D 直接在群里指定对应负责人：

- 文件接口、字段和 MinIO 问题找 A。
- 上传进度、分片和续传问题找 B。
- Token、登录跳转和权限问题找 C。
- 页面布局和业务入口问题由 D 处理。

## 6. 第三阶段：C 接正式登录态

C 完成登录页面和共享请求层后，在群里交付：

```text
authSession
共享 request
401 处理
403 处理
路由守卫
权限判断
两个测试账号
```

D 完成以下替换：

1. 文件 API 改用共享 `request`。
2. 删除临时 Token 客户端。
3. 使用 C 的 `authSession`。
4. 验证文件请求自动带 Bearer Token。
5. 验证 401 返回登录页。
6. 验证 403 显示无权限。
7. 验证退出登录后文件页面受保护。

B 配合检查上传任务中的 401 和登录恢复。

## 7. 第四阶段：大文件和断点续传

小文件跑通后进入第二轮：

```text
A 上传会话和分片合并
    ↓
B 分片上传和缺片续传
    ↓
D 大文件上传页面
```

### 7.1 A 的任务

A 提供：

```http
POST /api/v1/files/upload-sessions
GET  /api/v1/files/upload-sessions/{sessionId}
PUT  /api/v1/files/upload-sessions/{sessionId}/parts/{partNumber}
POST /api/v1/files/upload-sessions/{sessionId}/complete
```

查询会话响应包含：

```json
{
  "uploadedParts": [1, 2, 3],
  "missingParts": [4, 5, 6]
}
```

### 7.2 B 的任务

B 完成：

1. 大文件切片。
2. 分片 SHA-256。
3. 同时上传 3 个分片。
4. 分片失败重试。
5. 暂停和继续。
6. 刷新后读取未完成会话。
7. 只补缺失分片。
8. 分片完成后调用合并接口。

### 7.3 D 的任务

D 完成：

1. 大文件进度展示。
2. 暂停、继续和取消按钮。
3. 上传任务中心跨页面保持。
4. 合并完成后的提示。
5. 文件列表自动刷新。

## 8. 第五阶段：下载和安全验收

A 完成：

```text
普通下载
Range 下载
206 Partial Content
416 非法范围
ETag
文件归属校验
伪造扩展名校验
```

D 完成页面和接口验收：

1. 普通下载。
2. Range 返回 206。
3. 非法范围返回 416。
4. 账号 B 访问账号 A 的文件被拒绝。
5. 伪装成 PDF 的文件上传返回 400。
6. 文件列表只显示当前用户文件。

## 9. 最终合并顺序

D 按以下顺序合并：

```text
1. A 后端
2. C 登录态
3. B 上传器
4. D 页面
```

每次合并后 D 执行一次检查：

```text
后端能启动
前端能启动
登录能成功
文件列表能打开
小文件能上传
```

发现问题后在群里直接找对应负责人修复。

## 10. 最终验收顺序

D 按以下顺序执行：

1. 登录账号 A。
2. 上传小文件。
3. 上传多个小文件。
4. 上传大文件。
5. 暂停上传。
6. 刷新页面。
7. 重新选择同一文件。
8. 确认只补缺失分片。
9. 完成合并。
10. 普通下载。
11. Range 返回 206。
12. 非法 Range 返回 416。
13. 退出账号 A。
14. 登录账号 B。
15. 确认 B 看不到 A 的文件。
16. 用 B 请求 A 的 fileId，确认被拒绝。
17. 上传伪造扩展名文件，确认返回 400。
18. 提交截图、视频和最终说明。

## 11. 群内同步内容

每个成员完成阶段任务后，在群里发三行即可：

```text
完成了什么
其他人现在可以调用什么
下一步做什么
```

示例：

```text
A：小文件上传和文件列表已跑通。
接口是 POST /api/v1/files 和 GET /api/v1/files。
B、D 现在可以接真实接口，我继续做上传会话和分片。
```

## 12. 实际节奏

```text
第 1 天：
D 建 file-storage 分支，A/C/B/D 同时开始。

前几天：
A 做小文件，C 做 Token，B 做上传器，D 做文件页面。

中间：
A 小文件接口跑通，B 接真实接口，D 接文件列表。

之后：
A 做大文件和下载，B 做分片续传，D 做完整页面。

C 完成后：
D 切换正式登录态并验证 401、403 和路由守卫。

最后：
D 用两个账号完成上传、续传、下载、越权和扩展名校验。
```

## 13. 完成标准

- D 维护 `file-storage` 集成分支。
- A、B、C、D 的功能分支都先合入 `file-storage`。
- A 向 B 和 D 提供真实文件接口。
- C 向 B 和 D 提供正式 Token 接入。
- B 向 D 提供统一上传组件。
- D 完成文件页面和业务入口。
- 登录、上传、批量上传、大文件续传、下载和删除可用。
- 两个账号的数据彼此隔离。
- Range、ETag 和伪造扩展名验收通过。
- D 完成最终 Pull Request，将 `file-storage` 合入 `main`。
