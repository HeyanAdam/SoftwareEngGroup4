## 3. Outbox + MQ 链路

插入一条合成的 `sys_async_task` + `sys_message_outbox`（docId=999，无对应文档），观察全链路：

```text
sys_message_outbox   smoke-event-001  PUBLISHED  retry_count=0
sys_async_task       1  FAILED  retry_count=2  error=文档不存在：999
sys_message_consume_log  smoke-event-001  doc-parse-consumer  DEAD_LETTER  retry_count=3
kaoyan.doc.parse.dlq  1 条消息
```

说明：抢单 → publisher-confirm 确认 → 消费 → 任务 RUNNING → 流水线抛异常 → 回滚 + 重试 3 次 →
reject 进死信并置任务 FAILED，全部按设计执行。验证数据已清理（DLQ 中保留 1 条作为证据）。

## 4. 未覆盖项与偏差

| 项 | 说明 |
| --- | --- |
| 文件上传 / 分片合并 | 本地 compose 未含 MinIO，镜像仓库拉取被拒（denied），未能端到端验证；应用在 MinIO 不可用时正常启动并告警，上传返回 500。代码路径按「先对象后写库」实现 |
| 文档解析成功路径 | 需要 MinIO + Embedding API Key，本地缺失；失败/重试/死信路径已验证 |
| 审计 `resource_id` | 创建类接口没有资源 id（参数是名称/描述），该列为空；更新/删除类接口可从路径或首个数字参数取到 |
| `@MapperScan` | 未按方案扫根包：`platform/storage`、`platform/ai` 下的业务接口会被误注册成 Mapper 与真实 Bean 冲突，改为精确扫描 `modules` + `platform.messaging.mapper` + `platform.idempotency.mapper` |
| 队列名 | 文档解析队列改为 `kaoyan.doc.parse.queue` 以携带死信参数；旧 `doc_parse_queue` 可在 broker 手工删除 |
| MinIO 配置 | `MinioStorageService` 改为使用 `MinioProperties`（`minio.*`），修正原先 `kaoyan.storage.*` 未配置导致桶名回落为 `kaoyan` 的问题 |
| MyBatis 插件 Bean | `MybatisPlusInterceptor` 从 `WebConfig` 拆到 `MybatisConfig`，否则 `WebConfig → 幂等拦截器 → Mapper → 自动配置 → Interceptor[]` 形成 Bean 循环 |
