## 3. 第二次启动

同一数据库再次启动：

```text
Current version of schema: 6
Schema is up to date. No migration necessary.
RBAC V6 种子校验通过：权限 11 条，角色 4 个
```

第二次启动前后角色、权限和关系数量不变，`RbacInitializer` 只执行查询校验，不写数据库。

## 4. 已有数据库升级

预先创建 V1-V5 表，并插入一条绑定旧 `ADMIN` 角色的用户 `legacy_admin`，再用新版本启动：

```text
Schema history table does not exist yet
Successfully baselined schema with version: 0
Migrating schema to version "1 - baseline existing tables"
Migrating schema to version "2 - user profile and goal"
Migrating schema to version "3 - idempotency and audit"
Migrating schema to version "4 - file storage"
Migrating schema to version "5 - async task and outbox"
Migrating schema to version "6 - seed rbac dictionary"
Successfully applied 6 migrations, now at version v6
```

迁移后检查结果：

- 迁移历史包含版本 0 基线和 V1-V6，所有 `success=1`；
- 不再存在旧 `ADMIN` 角色；
- `legacy_admin` 已自动改绑 `SYSTEM_ADMIN`；
- 四个目标角色均启用；
- 未删除已有用户或其他业务数据；
- 启动过程仅提示本地 MinIO/Milvus 未启动，不影响数据库迁移和 RBAC 校验。

## 5. 复现命令

```powershell
cd backend
$env:DB_URL = 'jdbc:mysql://mysql-host:3306/kaoyan_ai_schema_test?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false'
$env:DB_USERNAME = '<user>'
$env:DB_PASSWORD = '<password>'
java -jar target/kaoyan-backend-1.0.0.jar
```

检查：

```sql
SELECT installed_rank, version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;

SELECT role_code, status FROM sys_role ORDER BY id;
SHOW TABLES;
```

已有库只需把 `DB_URL` 指向现有数据库后启动后端。首次启动会自动建立版本 0 基线并补齐 V1-V6；禁止手工修改已经合并的迁移文件或 `flyway_schema_history`。
