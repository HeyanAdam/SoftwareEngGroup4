# 数据持久化实现方案（V1 · 原生 MyBatis）

- 适用分支：`feat/persistence-foundation`
- 前提：Flyway V1–V6 已合并进 `main`，22 张表结构就绪；本方案只补**代码侧持久化**，表结构不动（仅新增 V7 索引）
- 框架决策：**新增持久化一律用原生 MyBatis**——Mapper 接口 + XML 映射 + 手写 SQL；不使用 `BaseMapper`、`Wrappers`、`@TableLogic`、`@Version`、`MetaObjectHandler` 等 MyBatis-Plus 特性
- 现有 `auth/user/chat/knowledge` 的 MyBatis-Plus 代码本次不迁移，保持可运行；新旧两套共存，新代码不再引入 MP API

---

## 一、现状与缺口

| 表族 | 表 | 当前状态 | 本方案要补 |
| --- | --- | --- | --- |
| 用户 | `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission` | 已落库（MP：entity + BaseMapper + 注解 SQL） | 本次不动 |
| 知识库/会话 | `kb_*`、`chat_*` | 已落库（MP） | 本次不动 |
| 画像/目标 | `user_profile`、`user_study_goal` | 只有表 | entity + Mapper + XML + service + 接口 |
| 日志/幂等 | `sys_idempotency_record`、`sys_login_log`、`sys_audit_log` | 只有表 | entity + Mapper + XML + 切面/拦截器 |
| 文件 | `file_object`、`file_upload_session`、`file_upload_part` | `modules/file` 只有一个 `package-info.java` | 三表全链路持久化 |
| 异步/消息 | `sys_async_task`、`sys_message_outbox`、`sys_message_consume_log` | 只有表，MQ 生产者直发、消费者空实现 | 任务状态机 + Outbox + 消费幂等 |

### 共存约定（写进 README）

1. `pom.xml` 保留 `mybatis-plus-spring-boot3-starter`：它内含 MyBatis 核心与 `SqlSessionFactory`，现有 MP 代码依赖它；不要换成 `mybatis-spring-boot-starter`，否则两套自动配置冲突。
2. 新代码 import 只允许 `org.apache.ibatis.*`，禁止 `com.baomidou.mybatisplus.*`，Code Review 检查项。
3. Mapper 接口放 `<模块>/mapper`，XML 放 `src/main/resources/mapper/<模块>/<Entity>Mapper.xml`，`namespace` 必须等于接口全限定名。
4. 现有 MP 实体不改造；新实体不继承 MP 基类、不加 `@TableName`/`@TableId`/`@TableField`。
5. MVP 结束后再统一迁移旧模块，不在本次范围。

### 已知坑

1. `KaoyanApplication` 的 `@MapperScan("com.group4.kaoyan.modules")` 扫不到 `platform` 下的 mapper，必须改为 `@MapperScan("com.group4.kaoyan")`。
2. 当前配置没有 `mapper-locations`，XML 不会被加载，必须补 `mybatis-plus.mapper-locations: classpath*:mapper/*/*.xml`。
3. `map-underscore-to-camel-case: true` 已开启，`resultType` 可直接映射驼峰；JSON/复杂字段仍要显式 `resultMap`。
4. `log-impl: StdOutImpl` 只适合本地，dev/prod 改 `org.apache.ibatis.logging.slf4j.Slf4jImpl`。
5. `DocParseConsumer` 失败后无条件 `basicNack(requeue=true)`，会死循环，P4 必须补重试上限 + 死信。
6. 二级缓存保持关闭，跨请求缓存走 Redis。

## 二、MyBatis 基础设施（P0，一个 PR 先合）

### 1. 配置

```yaml
mybatis-plus:
  mapper-locations: classpath*:mapper/**/*.xml
  type-aliases-package: com.group4.kaoyan.modules,com.group4.kaoyan.platform
  type-handlers-package: com.group4.kaoyan.common.mybatis
  configuration:
    map-underscore-to-camel-case: true
    default-statement-timeout: 30
    jdbc-type-for-null: 'NULL'
    log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl
```

- MP 的 `mybatis-plus.*` 就是 MyBatis 配置入口，**不要再加 `mybatis.*` 前缀**，二者只能生效一个
- 分页不引 PageHelper：新查询少，统一手写 `LIMIT #{offset}, #{size}` + 独立 `count` 语句

### 2. JSON 类型处理器

MySQL `JSON` 列默认只能给 `String`。新增：

```java
// common/mybatis/JsonTypeHandler.java
@MappedTypes({Object.class})
@MappedJdbcTypes(JdbcType.VARCHAR)
public class JsonTypeHandler extends BaseTypeHandler<Object> {
    private static final ObjectMapper MAPPER = new ObjectMapper()
            .registerModule(new JavaTimeModule())
            .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);

    @Override
    public void setNonNullParameter(PreparedStatement ps, int i, Object p, JdbcType t) throws SQLException {
        ps.setString(i, toJson(p));
    }
    // getNullableResult(ResultSet / String / Object) → fromJson(..., Object.class)
}
```

- 全局注册用 `type-handlers-package`（推荐）；也可在 `resultMap` 里 `<result typeHandler="...">` 显式写
- 需要 `List<String>` 的具体类型时，单独写 `StringListTypeHandler`，不要靠 `Object` 强转
- 写库是 `ps.setString`，MySQL 8 会校验格式；非法格式抛 SQL 异常，由 `GlobalExceptionHandler` 转 500

### 3. 时间与主键

- 不用 `MetaObjectHandler`（MP 专属）。service 写库前统一赋值 `createTime`/`updateTime`，或抽 `common/mybatis/EntityTimestamps.fill(entity)` 工具
- XML `insert` 一律 `useGeneratedKeys="true" keyProperty="id"`；批量插入不要依赖主键回填
- 表有 `DEFAULT CURRENT_TIMESTAMP`，但不要依赖：显式写入，保证应用与库时区一致

### 4. 分页与批量

```xml
<select id="selectPage" resultMap="BaseResultMap">
    SELECT * FROM sys_async_task
    <where>
        <if test="taskType != null">AND task_type = #{taskType}</if>
        <if test="status != null">AND status = #{status}</if>
    </where>
    ORDER BY id DESC
    LIMIT #{offset}, #{size}
</select>
```

- `offset = (pageNum - 1) * pageSize`，`pageSize` 上限 100
- 批量写用 `<foreach>` 拼 `INSERT ... VALUES`，JDBC URL 已有参数不要覆盖；需要批量优化时再加 `rewriteBatchedStatements=true`

### 5. 逻辑删除 / 乐观锁：手写，不用插件

- 逻辑删除：查询显式 `AND deleted = 0`，删除走 `UPDATE ... SET deleted = 1`，禁止物理 `DELETE` 业务表
- 乐观锁：`UPDATE ... SET ..., version = version + 1 WHERE id = #{id} AND version = #{version} AND deleted = 0`，返回 0 → `BizException(409, "数据已变更，请刷新")`
- 事务：service 写方法 `@Transactional(rollbackFor = Exception.class)`；MQ 发送不放进本地事务（走 Outbox）

```xml
<insert id="insert" parameterType="UserProfile" useGeneratedKeys="true" keyProperty="id">

        (user_id, gender, major, grade, base_level, weekly_study_minutes,
```

### P2 日志与幂等（`modules/audit` + `platform/idempotency`）

**登录日志**（`sys_login_log`）

- Mapper 只做 `insert`，无 update/delete
- `AuthService.login` 成功/失败都写；`@Transactional(propagation = REQUIRES_NEW)` + try/catch 吞异常：登录回滚不能带走日志，日志失败也不能阻断登录
- 字段：`account`、`success`、`ip`（`X-Forwarded-For` 首个非 unknown）、`user_agent`（截断 512）、`failure_reason`（密码错误/账号禁用/账号不存在分开记）
- 所有字符串写库前截断，避免 `DataIntegrityViolation`

**操作审计**（`sys_audit_log`）

```
modules/audit/annotation/AuditLog.java
modules/audit/aspect/AuditLogAspect.java
modules/audit/service/AuditLogService.java
modules/audit/entity/AuditLogRecord.java
modules/audit/mapper/AuditLogMapper.java
resources/mapper/audit/AuditLogMapper.xml
```

- 切点 `@annotation(AuditLog)`，只挂 `admin`、`kb`、`file` 写接口
- `resource_type`/`resource_id` 从注解 + 参数取；`after_json` 记返回体摘要（截断 8KB）
- `request_id` 由 Filter 生成并 `MDC.put("requestId")`
- 写库走 `@Async` + `REQUIRES_NEW`，不影响主流程
- Mapper 只有 `insert`，统计查询用 `selectByModule(module, from, to, offset, size)`

**接口幂等**（`sys_idempotency_record`）

```
platform/idempotency/Idempotent.java
platform/idempotency/IdempotencyRecord.java
platform/idempotency/IdempotencyMapper.java
platform/idempotency/IdempotencyService.java
platform/idempotency/IdempotencyInterceptor.java
resources/mapper/idempotency/IdempotencyMapper.xml
```

状态机 `0 PROCESSING / 1 SUCCESS / 2 FAILED`：

1. 读头 `Idempotency-Key`，缺失或 > 128 → 400
2. `selectByKey(user_id, endpoint, key)`：无记录 → `insert` PROCESSING（`expires_at = now + 24h`，`request_hash = sha256(body)`）后执行；SUCCESS → 回放响应；PROCESSING → 409；FAILED → 删记录后重试
3. 结束：成功 `updateResult(1, code, body)`，异常 `updateResult(2, ...)`
4. 并发保护靠 `uk_idempotency` 唯一索引：`insert` 抛 `DuplicateKeyException` 就重查分支处理，不用先查后插
5. `request_hash` 不一致 → 422
6. `IdempotencyCleanupJob`：`DELETE ... WHERE expires_at < NOW() LIMIT 1000` 循环

```xml
<update id="updateResult">
    UPDATE sys_idempotency_record
       SET status = #{status}, response_code = #{code},
           response_json = #{body, typeHandler=com.group4.kaoyan.common.mybatis.JsonTypeHandler},
           update_time = NOW()
     WHERE id = #{id} AND status = 0
</update>
```

`AND status = 0` 保证只有抢占者能写终态。

### P3 文件持久化（`modules/file`，从空模块补齐）

```
modules/file/entity/FileObject.java / FileUploadSession.java / FileUploadPart.java
modules/file/mapper/FileObjectMapper.java / UploadSessionMapper.java / UploadPartMapper.java
modules/file/service/FileService.java
modules/file/controller/FileController.java
resources/mapper/file/*.xml
```

| 场景 | 步骤 | 一致性处理 |
| --- | --- | --- |
| 小文件直传 | 先 `MinIO.putObject` → 再 `insert file_object(READY)` | DB 失败 → catch 里删对象；顺序不能反，否则「有记录没文件」 |
| 秒传 | `selectByOwnerAndHash(ownerId, sha256)` 命中 READY | 不新建对象，返回已有元数据 |
| 初始化分片 | `insert file_upload_session(INIT, part_size, part_count, expires_at=+24h)` | 重复 init 由前端复用 session |
| 上传分片 | 校验状态/序号 → MinIO 存分片 → `upsertPart`（唯一 `session_id+part_number`）→ `uploaded_count++` | 先落对象再写库，写库失败删对象 |
| 合并 | 校验分片齐全 → MinIO 合并 → session `COMPLETED` + `insert file_object` | 合并失败 session `FAILED`，分片保留供重试 |
| 下载 | `selectByIdForOwner(id, ownerId)` 且 `deleted=0 AND status='READY'` → 预签名 URL | 不存在 404，不透 MinIO 错误 |
| 删除 | `UPDATE ... SET deleted = 1` + 删 MinIO 对象 | 对象删除失败只记日志 |
| 清理 | `UploadCleanupJob` 扫 `IN (INIT,UPLOADING) AND expires_at < NOW()` → CANCELLED + 删分片 | 按 id 处理，重复执行无副作用 |

分片 UPSERT 用 MySQL 语法，不用 `INSERT IGNORE`（会吞字段更新）：

```xml
<insert id="upsertPart" parameterType="FileUploadPart">
    INSERT INTO file_upload_part (session_id, part_number, part_size, part_hash,
                                  bucket_name, object_key, status, create_time, update_time)
    VALUES (#{sessionId}, #{partNumber}, #{partSize}, #{partHash},
            #{bucketName}, #{objectKey}, 'UPLOADED', NOW(), NOW())
    ON DUPLICATE KEY UPDATE
        part_size = VALUES(part_size), part_hash = VALUES(part_hash),
        bucket_name = VALUES(bucket_name), object_key = VALUES(object_key),
        status = 'UPLOADED', update_time = NOW()
</insert>
```

`scene` 限定枚举（`AVATAR/QUESTION_IMAGE/STUDY_MATERIAL/KNOWLEDGE_DOCUMENT/CHAT_ATTACHMENT`），非法 400。

### P4 异步任务 + Outbox + 消费幂等（`platform/messaging`）

```
platform/messaging/entity/AsyncTask.java / MessageOutbox.java / ConsumeLog.java
platform/messaging/mapper/AsyncTaskMapper.java / OutboxMapper.java / ConsumeLogMapper.java
platform/messaging/service/AsyncTaskService.java / OutboxService.java / ConsumeLogService.java
platform/messaging/job/OutboxPublisherJob.java / AsyncTaskRecoveryJob.java
resources/mapper/messaging/*.xml
```

任务状态机（对外映射：`PENDING/RETRY_WAIT`→`QUEUED`，`RUNNING`→`PROCESSING`）：

```
PENDING → RUNNING → SUCCEEDED
              ↓
          RETRY_WAIT → RUNNING ... → FAILED（超 maxRetry）
任意 → CANCELLED
```

- `createTask`：`task_no = type + "-" + yyyyMMddHHmmss + "-" + 6 位随机`，`uk_async_task_no` 兜底
- `RUNNING` 超 10 分钟由 `AsyncTaskRecoveryJob` 拉回 `RETRY_WAIT`
- 退避：`next_retry_at = NOW() + min(30s × 2^retry_count, 10min)`
- 状态更新全部条件 UPDATE：

```xml
<update id="markRunning">
    UPDATE sys_async_task
       SET status = 'RUNNING', progress = #{progress}, update_time = NOW()
     WHERE id = #{id} AND status IN ('PENDING','RETRY_WAIT')
</update>

<update id="finish">
    UPDATE sys_async_task
       SET status = #{status},
           progress = CASE WHEN #{status} = 'SUCCEEDED' THEN 100 ELSE progress END,
           result_json = #{resultJson, typeHandler=com.group4.kaoyan.common.mybatis.JsonTypeHandler},
           error_message = #{errorMessage}, finished_time = NOW(), update_time = NOW()
     WHERE id = #{id} AND status IN ('RUNNING','RETRY_WAIT')
</update>
```

影响行 0 说明被取消或已被其他实例处理，直接返回。

**Outbox**：业务写库 + outbox 写库同一本地事务。

```java
@Transactional(rollbackFor = Exception.class)
public void createDocParseTask(...) {
    asyncTaskMapper.insert(task);
    outboxMapper.insert(outbox);   // event_id 作为消息 messageId
}
```

`OutboxPublisherJob`（`@Scheduled(fixedDelay = 2000)`，`@Profile("!test")`）：

1. 抢单：`UPDATE ... SET status='PUBLISHING' WHERE id=? AND status IN ('PENDING','RETRY_WAIT')`，影响行 0 跳过（多实例安全）
2. 发送：`rabbitTemplate.convertAndSend(exchange, routingKey, payload, m -> m.setMessageId(eventId))`，开 publisher-confirm，ack 才置 `PUBLISHED + published_at`
3. 失败：`retry_count++` + 退避，> 5 次置 `FAILED` 并告警
4. 卡在 `PUBLISHING` > 5 分钟由同一 job 复位

**消费幂等**：`DocParseConsumer` 先 `insert` consume_log（唯一 `message_id+consumer_name`）

- 插入成功 → 执行业务；成功 `SUCCEEDED` + `basicAck`
- 已存在且 SUCCEEDED → 直接 ack
- 已存在且 PROCESSING 但 `update_time < NOW()-10min` → 视为上次中断，允许重跑
- 失败：`retry_count++`，`< 3` 则 `basicNack(requeue=true)`，否则 `basicReject(requeue=false)` 进死信 `kaoyan.doc.parse.dlq`，同时任务置 FAILED
- `RabbitTopologyConfig` 补 `kaoyan.dlx` + 死信队列 + `x-dead-letter-exchange`，DLX 先声明
- `DocumentProcessService` 解析结果落 `kb_document.status`/`raw_text` + `kb_document_chunk`，与 `AsyncTask.finish(SUCCEEDED)` 同一事务

## 七、风险与回滚

- XML 与接口不同步会在启动/调用时报 `BindingException`，CI 用 Testcontainers 全量扫描可拦截
- 两套 ORM 混用：MP 的 `mybatis-plus.*` 就是 MyBatis 配置入口，不要同时加 `mybatis.*`，否则只有一套生效
- Outbox 积压：监控 `FAILED` 数量，`PUBLISHING` 卡死靠 job 复位
- 日志表增长：`sys_login_log`/`sys_audit_log` 保留 90/180 天，本次只做幂等表清理
- 回滚：各阶段独立 PR，只回代码不回 Flyway 历史；V7 索引可 `DROP INDEX` 回退
