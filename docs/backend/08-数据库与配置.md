## 一、数据库表

路径：`backend/src/main/resources/db/schema.sql`
执行：`spring.sql.init` 每次启动跑一次（全部 `CREATE TABLE IF NOT EXISTS`，幂等），
或由 `deploy/docker-compose.yml` 挂进 MySQL 的 `docker-entrypoint-initdb.d`。

> 脚本里**故意不写 `CREATE DATABASE` / `USE`**：它作用于“当前连接的库”。
> 这样容器 initdb（`MYSQL_DATABASE=kaoyan_ai`）和后端 `DB_URL` 指向的库都是同一个，
> 改库名不用改这个文件。

### RBAC 五张表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sys_user` | `username` UNIQUE、`password_hash`、`status` | 用户；密码 BCrypt |
| `sys_role` | `role_code` UNIQUE | 角色（`ADMIN` / `STUDENT`） |
| `sys_permission` | `perm_code` UNIQUE、`perm_type` | 权限字典（11 条 API 权限） |
| `sys_user_role` | `uk_user_role(user_id, role_id)` | 用户↔角色 |
| `sys_role_permission` | `uk_role_permission(role_id, permission_id)` | 角色↔权限 |

### 知识库三张表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `kb_knowledge_base` | `name`、`user_id`、`visibility`、`doc_count` | `visibility`：0 私有 / 1 公开；管理员建库默认 1 |
| `kb_document` | `kb_id`、`object_key`、**`raw_text` LONGTEXT**、`content_hash`、`status`、`error_msg` | 原件在 MinIO，解析全文落 `raw_text` |
| `kb_document_chunk` | `doc_id`、`chunk_index`、`content`、`milvus_id` | 切片正文；`milvus_id = id` |

### 会话两张表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `chat_conversation` | `user_id`、`kb_id`、`deleted` | 软删除 |
| `chat_message` | `conversation_id`、`role`、`content`、`references_json`、`model_name` | `references_json` 按角色分级写入 |

### 一份数据存在哪（容易搞混）

| 数据 | 存哪 | 备注 |
| --- | --- | --- |
| 原始文件（PDF/DOCX） | MinIO bucket `kaoyan-files` | 可下载原件 |
| 解析后的全文 | `kb_document.raw_text` | 重解析不用回 MinIO |
| 切片正文 | `kb_document_chunk.content` | MySQL 侧副本 |
| 切片向量 + 正文 + 文件名 | Milvus `doc_chunk` | 检索只打这里，不 JOIN MySQL |
| 用户 / 角色 / 权限 | MySQL | 重启保留 |

## 二、配置分层

```
deploy/.env                                  ← 全项目唯一环境文件（复制自 .env.example）
      ↓ spring.config.import（可选，存在才读）
backend/src/main/resources/config/application.yml       ← 公共配置 + ${ENV:默认值}
backend/src/main/resources/config/application-dev.yml   ← 开发：Swagger 开、日志 debug
backend/src/main/resources/config/application-prod.yml  ← 生产：Swagger 关、日志 warn + 文件
      ↓ 覆盖
系统环境变量 / 命令行参数                       ← 优先级最高
```

### 为什么配置文件在 `resources/config/` 而不是 `resources/`

Spring Boot 默认的配置搜索路径就包含 `classpath:/config/`，所以放进子目录**不需要额外配置**，
`mvn spring-boot:run`、`java -jar`、容器内运行都能读到。

### 后端自动读 `deploy/.env`

路径：`backend/src/main/resources/config/application.yml`

```yaml
spring:
  config:
    import:
      - optional:file:./deploy/.env[.properties]     # 从仓库根目录跑
      - optional:file:../deploy/.env[.properties]    # 从 backend/ 跑（IDE 默认）
      - optional:file:./env/.env[.properties]        # 可选个人覆盖
      - optional:file:../backend/env/.env[.properties]
```

- `[.properties]` 是让 Spring 用 properties 解析器读这个无扩展名文件；
- `optional:` 表示文件不存在也不报错，所以容器里（环境变量直接注入）不受影响；
- **后面的条目优先级更高**，所以 `backend/env/.env` 可以覆盖 `deploy/.env` 的同名键。

### 自动建表

```yaml
spring:
  sql:
    init:
      mode: ${DB_INIT_MODE:always}
      schema-locations: classpath:db/schema.sql
      encoding: UTF-8
```

`always` 表示每次启动都执行；脚本幂等，所以重复执行无副作用。
如果用 `deploy/` 里的 MySQL（没有 initdb 挂载），靠这条自动建表。

## 三、环境变量（`deploy/.env.example`）

路径：`deploy/.env.example`

| 分组 | 变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| 后端 | `SPRING_PROFILES_ACTIVE` | `dev` | 切 dev/prod |
| 后端 | `SERVER_PORT` | `8080` | 应用端口 |
| 后端 | `DB_INIT_MODE` | `always` | 需要的话设 `never` 关掉自动建表 |
| 后端 | `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | `localhost:3306/kaoyan_ai`、`kaoyan`、`kaoyan123` | 本机连容器里的 MySQL |
| MySQL | `MYSQL_ROOT_PASSWORD` / `MYSQL_DATABASE` / `MYSQL_USER` / `MYSQL_PASSWORD` | `root123456` / `kaoyan_ai` / `kaoyan` / `kaoyan123` | 容器初始化 |
| Redis | `REDIS_PORT` / `REDIS_PASSWORD` | `6379` / 空 | |
| RabbitMQ | `RABBITMQ_*` | `kaoyan/kaoyan123` | 目前后端未使用，预留 |
| MinIO | `MINIO_ROOT_USER/PASSWORD`、`MINIO_API_PORT/CONSOLE_PORT`、`MINIO_BUCKET` | `minioadmin`、9000/9001、`kaoyan-files` | |
| Milvus | `MILVUS_PORT`、`MILVUS_COLLECTION`、`MILVUS_DIMENSION`、`VECTOR_TOP_K`、`VECTOR_SCORE_THRESHOLD` | 19530 / `doc_chunk` / 1024 / 6 / 0.3 | |
| 模型 | `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_TEMPERATURE`、`LLM_MAX_TOKENS` | DeepSeek / `deepseek-chat` | Key 必填 |
| 向量模型 | `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSION`、`EMBEDDING_BATCH_SIZE` | / `bge-m3` / 1024 / 16 | **维度要与 `MILVUS_DIMENSION` 一致** |
| 切片 | `CHUNK_SIZE` / `CHUNK_OVERLAP` / `HISTORY_ROUNDS` | 400 / 80 / 6 | |

`backend/env/.env.example` 是**可选覆盖模板**，只写要覆盖的键（例如自己的 Key），不需要全量复制。

### 配置绑定类

路径：`backend/src/main/java/com/group4/kaoyan/common/config/AiProperties.java`

`@ConfigurationProperties(prefix = "kaoyan")`，对应 `application.yml` 的 `kaoyan:` 段
（`llm` / `embedding` / `milvus` / `storage` / `rag`）。新增配置项要**两处同时改**：
Java 字段 + yml 键，否则启动时绑定不上。

## 四、启动顺序

```powershell
# 1. 配置
cd deploy
Copy-Item .env.example .env        # 填 LLM_API_KEY、EMBEDDING_API_KEY

# 2. 中间件（MySQL/Redis/RabbitMQ/MinIO/Milvus(+etcd)/Mailpit/Nginx）
docker compose up -d
docker compose ps                  # 等 mysql、milvus 变 healthy

# 3. 后端
cd ..\backend
mvn spring-boot:run
```

日志里应该看到：

```
The following 1 profile is active: "dev"
Milvus 已连接 localhost:19530，collection=doc_chunk，维度=1024
RBAC 初始化检查完成：权限字典 11 条；管理员由首个注册用户产生
Tomcat started on port 8080
```

之后：

1. `POST /api/auth/register` 注册 → **第一个用户自动是管理员**（日志会打）；
2. `POST /api/auth/login` 拿 token；
3. 用 admin token 建库、传文档、等 `status=READY`；
4. 普通用户注册后用 `/api/chat/stream` 提问（拿不到引用，这是设计）。

全容器化（含后端镜像）：

```powershell
cd deploy
docker compose --profile app up -d --build
```

## 五、端口与依赖

| 服务 | 端口 | 后端是否必需 |
| --- | --- | --- |
| MySQL | 3306 | ✅ 必需 |
| Redis | 6379 | ⬜ 目前未使用（Sa-Token 用默认内存会话） |
| RabbitMQ | 5672 / 15672 | ⬜ 预留 |
| MinIO | 9000 / 9001 | ✅ 上传/解析必需 |
| Milvus | 19530 / 9091 | ✅ 检索/向量化必需 |
| etcd | 不暴露 | ✅ Milvus 依赖 |
| Mailpit | 1025 / 8025 | ⬜ 预留 |
| Nginx | 8088 | ⬜ 反向代理用 |
| 后端 | 8080 | — |

MySQL / MinIO / Milvus 三者缺一个的影响不同：

- **MySQL 缺**：启动时 `spring.sql.init` 就失败，应用起不来（`HikariPool` 初始化异常）；
- **MinIO 缺**：启动只 `warn`，能起；上传/解析会失败；
- **Milvus 缺**：启动只 `warn`，能起；检索返回空、向量写入失败。

## 六、常见故障对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Table 'xxx.sys_user' doesn't exist` | 库名与 `DB_URL` 不一致，或自动建表被关 | 检查 `DB_URL` 的库名；确认 `DB_INIT_MODE=always` |
| 启动报 `Communications link failure` | MySQL 没起 / 端口不对 | `docker compose ps`，检查 3306 |
| 上传后一直 `UPLOADED` | `documentExecutor` 队列满或解析失败 | 查 `kb_document.status/error_msg`，看日志 `文档处理失败` |
| 检索永远空 | Milvus 没起、collection 为空、阈值太高 | 查 Milvus 日志；调低 `VECTOR_SCORE_THRESHOLD` |
| 写入 Milvus 报维度不匹配 | `EMBEDDING_DIMENSION` 与 collection 维度不同 | 删 collection 让它按新维度重建，再全量 reindex |
| 403 `缺少权限：xxx` | 角色没这个权限码 | 后台 `PUT /api/admin/roles/{id}/permissions` 补上 |
| 登录返回 401 | token 过期（30 天） | 重新登录 |
| 改了 `deploy/.env` 但没生效 | 进程没重启 / 正在用系统环境变量覆盖 | 重启；检查 IDE Run Configuration 里是否也设了同名变量 |
