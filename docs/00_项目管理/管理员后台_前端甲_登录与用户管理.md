# 管理员后台前端（甲）：登录、壳层与用户管理

> 参考资料：《后台管理员登录与角色权限分配——设计与实施步骤》
> 基线：`main` @ `10ba297` 及之后的管理员后台公共约定
> 目标：负责禅道风格后台的登录页、独立登录态、后台壳层和用户角色分配页。

## 1. 甲的交付范围

甲负责：

- 管理员独立 Token 和后台登录态。
- `/admin/login` 管理员登录页。
- `/admin` 后台路由树、权限守卫和 401 分流。
- 禅道风格 `AdminLayout`：顶栏、左侧菜单、面包屑、折叠和退出。
- `/admin/users` 用户列表、分页、筛选、启停和角色分配抽屉。
- `/admin/dashboard` 占位路由，给数据大屏组后续替换。
- 管理员登录、路由守卫、用户角色分配的前端测试。

甲不负责：

- 角色权限矩阵页面。
- 权限字典和登录日志页面。
- 数据大屏的统计接口和图表。

## 2. 开工前置条件

### 2.1 管理员准入口径

后台不能只允许 `SYSTEM_ADMIN`。统一规则：

- 用户拥有任意 `admin:*` 权限，就可以进入后台壳层。
- 每个菜单继续按自己的权限码显隐。
- `DATA_AUDITOR` 只拥有 `admin:user:list`、`admin:role:list` 时，可以进入只读页面。
- 学生没有 `admin:*` 权限，不能进入后台。

### 2.2 后台 Token

学生端 Token：

```text
sa_token
```

后台 Token：

```text
sa_admin_token
```

两个 Store 和两个请求实例必须隔离。退出后台不能误删学生登录态。

### 2.3 后端依赖

甲需要后端提供或确认：

- `POST /api/v1/auth/login`
- `GET /api/v1/auth/captcha`
- `GET /api/v1/auth/me`
- `POST /api/v1/auth/logout`
- `GET /api/v1/admin/users`
- `GET /api/v1/admin/users/{id}`
- `PUT /api/v1/admin/users/{id}/status`
- `GET /api/v1/admin/users/{id}/roles`
- `PUT /api/v1/admin/users/{id}/roles`
- `GET /api/v1/admin/roles`

后端暂未提供时，甲使用 typing 明确的 mock 数据开发，不阻塞页面结构。

管理员账号当前是一个实际阻塞项。开工前需要由后端或集成负责人通过 `KAOYAN_ADMIN_USERNAME / KAOYAN_ADMIN_PASSWORD` 创建真实管理员，不能依赖前端 Mock。

## 4. 步骤 A1：改造公共请求层

修改 `frontend/src/shared/api/request.ts`。

### 4.1 抽出 tokenKey

```ts
export const TOKEN_STORAGE_KEY = 'sa_token'
export const ADMIN_TOKEN_STORAGE_KEY = 'sa_admin_token'

function createService(
  baseURL: string,
  tokenKey: string = TOKEN_STORAGE_KEY,
): AxiosInstance {
  // ...
}
```

请求拦截器根据 `tokenKey` 读取 token：

```ts
const token = localStorage.getItem(tokenKey)
if (token) config.headers.set('Authorization', `Bearer ${token}`)
```

### 4.2 新增后台认证实例

```ts
export const adminAuthRequest = createService(
  API_BASE_URL,
  ADMIN_TOKEN_STORAGE_KEY,
)

export const adminRequest = createService(
  ADMIN_API_BASE_URL,
  ADMIN_TOKEN_STORAGE_KEY,
)
```

新增：

```text
adminAuthGet
adminAuthPost
```

现有 `adminGet/adminPost/adminPut/adminDel` 改为使用 `adminRequest`。

### 4.3 401 分流

`UNAUTHORIZED_EVENT` 的 detail 至少包含：

```ts
{
  scope: 'user' | 'admin',
  code,
  message,
  requestId,
}
```

管理员 401 清 `sa_admin_token`，学生 401 才清 `sa_token`。

### 4.4 验收

- 学生端请求不读取 `sa_admin_token`。
- 后台请求不读取 `sa_token`。
- 后台 401 不影响已经登录的学生会话。
- `npm run build` 不出现类型错误。

## 5. 步骤 A2：新增管理员登录态

新增 `frontend/src/app/stores/adminAuth.ts`。

状态：

```ts
token
userId
username
nickname
roles
permissions
```

动作：

```text
setLoginResult
setToken
loadCurrentUser
logout
clearAuth
hasPermission
hasAnyAdminPermission
```

`hasAnyAdminPermission`：

```ts
return this.permissions.some((code) => code.startsWith('admin:'))
```

规则：

- 登录成功先保存 `sa_admin_token`。
- `loadCurrentUser` 调 `adminAuthGet('/auth/me')`。
- 退出时尽力调用 `/auth/logout`，无论成功都清后台状态。
- 不修改学生端 `auth` Store。

## 6. 步骤 A3：管理员登录页

新增：

```text
frontend/src/features/admin/login/AdminLoginPage.vue
frontend/src/features/admin/login/styles/admin-login.css
```

### 6.1 视觉

模仿禅道后台的信息层级，但不复制其品牌素材：

- 桌面左侧约 55% 深绿品牌区。
- 桌面右侧约 45% 白色登录卡。
- 窄屏改为顶部品牌条 + 单列表单。
- 页面不显示学生端侧栏。

### 6.2 功能

- 挂载时获取验证码。
- 账号、密码、图形验证码。
- 回车提交。
- loading 防止重复。
- 换图按钮。
- 10005 清空验证码并换图。
- 10010/429 跳 `/429`。
- 10003 显示锁定时间。
- 其他登录错误保留账号，密码按安全习惯清空。
- “返回学生端”跳 `/login`。

### 6.3 登录后的准入

登录成功先写后台 Store，再检查：

```ts
const canEnter = result.permissions.some((code) => code.startsWith('admin:'))
```

若为假：

1. 调后台 Store 的 `clearAuth()`。
2. 提示“当前账号没有后台管理权限”。
3. 跳 `/403`。

若为真：

```ts
router.replace(
  typeof route.query.redirect === 'string'
    ? route.query.redirect
    : '/admin/dashboard',
)
```

### 6.4 后端增强协调

后端后续增加 `scope: 'ADMIN'` 时，前端只透传该字段，不改变页面结构：

```ts
loginWithPassword({
  ...payload,
  scope: 'ADMIN',
})
```

服务端准入必须按任意 `admin:*` 权限，不得硬编码 `SYSTEM_ADMIN`。

## 7. 步骤 A4：路由与守卫

修改 `frontend/src/app/router/index.ts`。

### 7.1 顶层路由

```ts
{
  path: '/admin/login',
  name: 'AdminLogin',
  component: () => import('../../features/admin/login/AdminLoginPage.vue'),
  meta: { requiresAuth: false, adminScope: true },
}
```

```ts
{
  path: '/admin',
  component: () => import('../../features/admin/layout/AdminLayout.vue'),
  meta: { requiresAuth: true, adminScope: true },
  children: [
    { path: '', redirect: '/admin/dashboard' },
    {
      path: 'dashboard',
      name: 'AdminDashboard',
      component: () => import('../../features/admin/overview/AdminOverviewPage.vue'),
      meta: { permission: 'admin:user:list' },
    },
    {
      path: 'users',
      name: 'AdminUsers',
      component: () => import('../../features/admin/users/AdminUsersPage.vue'),
      meta: { permission: 'admin:user:list' },
    },
    {
      path: 'roles',
      name: 'AdminRoles',
      component: () => import('../../features/admin/roles/AdminRolesPage.vue'),
      meta: { permission: 'admin:role:list' },
    },
    {
      path: 'permissions',
      name: 'AdminPermissions',
      component: () => import('../../features/admin/permissions/AdminPermissionsPage.vue'),
      meta: { permission: 'admin:role:list' },
    },
    {
      path: 'logs',
      name: 'AdminLogs',
      component: () => import('../../features/admin/logs/AdminLogsPage.vue'),
      meta: { permission: 'admin:user:list' },
    },
  ],
}
```

乙新增角色页前，可以先放占位组件，避免甲修改乙的文件。

### 7.2 `RouteMeta`

增加：

```ts
adminScope?: boolean
```

### 7.3 守卫

- 按 `adminScope` 选择 `useAdminAuthStore` 或 `useAuthStore`。
- 未登录跳对应登录页。
- 刷新时调用对应 `loadCurrentUser`。
- 后台只验证具体 `permission`，不再强制角色等于 `SYSTEM_ADMIN`。

### 7.4 学生端入口

保留 `MainLayout` 的“管理后台”链接：

```text
/admin/dashboard
```

显隐仍使用 `admin:user:list` 或 `admin:role:list`。

### 8.2 侧栏

建议菜单：

```text

角色权限    /admin/roles
```

显隐：

- 用户管理和登录日志：`admin:user:list`

### 8.3 折叠

```text
localStorage['admin_sidebar_collapsed']
```

刷新后恢复。

### 8.4 退出

- 调 `adminAuthStore.logout()`。
- 只清 `sa_admin_token`。
- 跳 `/admin/login`。

## 9. 步骤 A6：用户与角色分配页

新增：

```text
frontend/src/features/admin/users/AdminUsersPage.vue
frontend/src/features/admin/users/components/AssignRoleDrawer.vue
```

### 9.1 用户列表

列：

- 用户 ID
- 用户名
- 昵称
- 脱敏邮箱
- 状态
- 角色标签
- 操作

筛选：

- 关键词
- 状态
- 查询
- 重置

分页使用：

```text
page_num
page_size
```

### 9.2 状态开关

切换时立即调用：

```http
PUT /api/v1/admin/users/{id}/status
{"status":0}
```

请求失败时回滚 UI，并保留原状态。

### 9.3 分配角色抽屉

- 打开时加载所有角色。
- 高亮当前用户已绑定角色。
- 保存调用：

```http
PUT /api/v1/admin/users/{id}/roles
{"ids":[1,3]}
```

- 最后一个 `SYSTEM_ADMIN` 保护由后端判断，前端原样展示错误。
- 成功后刷新当前用户角色标签。

### 9.4 权限控制

- 用户列表需要 `admin:user:list`。
- 启停和分配角色按钮需要 `admin:user:update`。
- `DATA_AUDITOR` 可以看到用户页和角色标签，但看不到修改按钮。
