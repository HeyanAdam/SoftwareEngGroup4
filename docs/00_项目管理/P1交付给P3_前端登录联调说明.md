# P1 交付给 P3：登录与权限前端联调说明

> 交付人：P1（认证后端）　接收人：P3（前端登录与权限联调）
> 版本：V1（2026-11-19）　后端分支 `feat/auth-backend-authentication`
> 服务地址：`http://localhost:8080`（经 Nginx 走 `http://localhost:8088`）

---

## 1. 通用约定（先看这一节）

| 项 | 约定 |
|---|---|
| 前缀 | `/api/v1/auth`（**旧的 `/api/auth/*` 已删除，调了会 404**） |
| 请求头 | `Content-Type: application/json` |
| 响应体 | 统一 `{ "code": 0, "message": "success", "data": ... }`，`code=0` 为成功 |
| 字段命名 | **全部 snake_case**（`captcha_key`、`expires_in`、`user_id`、`has_profile`…） |
| Token | 登录/注册成功后放在响应体 `data.token`，后续请求头带 `Authorization: Bearer <token>` |
| 有效期 | `expires_in = 2592000` 秒（30 天），前端存 localStorage 即可 |
| 状态码 | 错误时 **HTTP 状态码也会变**（401/403/409/423/429），不要只看 `code` |
| 限流 | 429 响应带 `Retry-After: <秒>`，锁定 423 也带，前端要显示倒计时 |

接口总览：

| 方法 | 路径 | 需登录 | 说明 |
|---|---|---|---|
| GET | `/api/v1/auth/captcha` | 否 | 取图形验证码 |
| POST | `/api/v1/auth/verification-codes` | 否 | 发邮箱验证码 |
| POST | `/api/v1/auth/register` | 否 | 注册，需 `Idempotency-Key`，成功 **201** |
| POST | `/api/v1/auth/login` | 否 | 登录，两种方式 |
| GET | `/api/v1/auth/me` | **是** | 当前用户 |
| POST | `/api/v1/auth/logout` | **是** | 退出 |
| POST | `/api/v1/auth/password-reset` | 否 | 重置密码，需 `Idempotency-Key` |

## 2. 图形验证码

`GET /api/v1/auth/captcha`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "captcha_key": "cap_8f31c2a0e9",
    "image_base64": "data:image/png;base64,iVBORw0KGgo...",
    "expires_in": 300
  }
}
```

- `image_base64` 已含 Data URI 前缀，**直接 `img.src = data.image_base64`**，不要再拼 `data:image/png;base64,`。
- 图形码 4 位、大小写混合字母与数字，**按用户输入原样提交即可**（后端忽略大小写差异由实现保证，前端不要转大写）。
- 有效期 5 分钟；**同一个 `captcha_key` 连续输错 3 次即作废**，需重新获取。
- 刷新按钮：重新调本接口，替换旧的 `captcha_key`。
- 限流：同 IP 30 次/分钟，超限 `429 + 10010`。

---

## 3. 发送邮箱验证码

`POST /api/v1/auth/verification-codes`

```json
{ "email": "student@example.com", "purpose": "REGISTER" }
```

`purpose` 只允许三个值：`REGISTER`（注册）、`EMAIL_LOGIN`（验证码登录）、`RESET_PASSWORD`（重置密码）。**三个用途的验证码互不通用**，注册页只能用 `REGISTER`。

成功：

```json
{
  "code": 0,
  "message": "验证码已发送",
  "data": { "expires_in": 300, "retry_after": 60 }
}
```

- 有效期 5 分钟，60 秒内不可重发。
- 重发按钮按 `retry_after` 做 60 秒倒计时；60 秒内再次点击会返回 `400 + 10005`（提示"发送过于频繁，请 x 秒后再试"，文案后端会给）。
- 同 IP 每小时最多 10 封，超限 `429 + 10010`。
- 本地联调收信：Mailpit `http://localhost:8025`。

## 4. 注册

`POST /api/v1/auth/register`　**请求头必须带 `Idempotency-Key`（建议 `uuid()` 生成，一次提交一个）**

```json
{
  "username": "kaoyan_student",
  "email": "student@example.com",
  "verify_code": "482913",
  "password": "KaoYan@2026",
  "confirm_password": "KaoYan@2026",
  "nickname": "考研小白",
  "agree_agreement": true
}
```

成功：**HTTP 201**

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "user_id": 10001,
    "username": "kaoyan_student",
    "nickname": "考研小白",
    "token": "sa-token-value",
    "token_type": "Bearer"
  }
}
```

- 注意 **201 不是 200**，`axios` 默认只认 2xx 没问题，但自己写 `if (status === 200)` 会漏判。
- 注册成功**直接返回 token**，可以免登录直接进首页；也可以让用户再登一次。
- 注册一律绑定 `STUDENT` 角色（`chat:send` 一个权限），不存在"第一个注册用户是管理员"的规则。
- 幂等：同一 `Idempotency-Key` 重复提交会返回首次的结果，不会重复建号；不传键 → `400 + 10000`。

## 5. 登录

`POST /api/v1/auth/login`

### 5.1 用户名/邮箱 + 密码

```json
{
  "login_type": "PASSWORD",
  "account": "kaoyan_student",
  "password": "KaoYan@2026",
  "captcha_key": "cap_8f31c2a0e9",
  "captcha_code": "7K9p"
}
```

`account` 填用户名或邮箱都行。

### 5.2 邮箱验证码

```json
{
  "login_type": "EMAIL_CODE",
  "email": "student@example.com",
  "verify_code": "482913"
}
```

这条**不需要图形验证码**；验证码用 `purpose=EMAIL_LOGIN` 的那一封。

### 5.3 成功响应（两种方式一致）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "sa-token-value",
    "token_type": "Bearer",
    "expires_in": 2592000,
    "user_id": 10001,
    "username": "kaoyan_student",
    "nickname": "考研小白",
    "roles": ["STUDENT"],
    "permissions": ["chat:send"],
    "has_profile": false
  }
}
```

- `roles` / `permissions` 是**权限快照**，前端按钮显隐直接用它，不要自己按角色名硬编码。
- `has_profile=false` 时引导去完善资料页。

## 6. 当前用户

`GET /api/v1/auth/me`（需 `Authorization: Bearer <token>`）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user_id": 10001,
    "username": "kaoyan_student",
    "nickname": "考研小白",
    "email_masked": "stu***@example.com",
    "roles": ["STUDENT"],
    "permissions": ["chat:send"],
    "has_profile": false
  }
}
```

- 邮箱是**脱敏**的，要显示完整邮箱得另外接口（前端别指望这里返回原文）。
- 刷新页面后调这个接口恢复登录态，比读 localStorage 里的 `permissions` 可靠（权限被后台改过会即时生效）。
- 未登录/Token 失效 → `401 + 10001`，直接跳登录页并清掉本地 token。

---

## 7. 退出登录

`POST /api/v1/auth/logout`（需登录）

```json
{ "code": 0, "message": "退出成功", "data": null }
```

前端收到成功即清 localStorage 并跳登录页；即使返回 401 也要清本地状态（token 已经无效）。

---

## 8. 重置密码

`POST /api/v1/auth/password-reset`　**必须带 `Idempotency-Key`**

```json
{
  "email": "student@example.com",
  "verify_code": "482913",
  "new_password": "NewKaoYan@2027",
  "confirm_password": "NewKaoYan@2027"
}
```

成功：

```json
{ "code": 0, "message": "密码已重置，请重新登录", "data": null }
```

**重置成功后该用户所有旧 Token 立即失效**（含其他设备），前端必须清本地 token 并跳登录页。

## 9. 错误处理表（前端分支逻辑照这个做）

| HTTP | code | 前端动作 |
|---|---|---|
| 400 | 10000 | 表单级提示，展示 `message`（后端会把字段名带上，如 `email 格式不正确`） |
| 400 | 10005 | 验证码错误/过期/超次 → 清空验证码输入，图形码顺便刷新 |
| 400 | 10006 | 两次密码不一致，红字提示 |
| 400 | 10012 | 请求方式不对，属开发期 bug |
| 401 | 10001 | 清 token，跳登录页（静默，不要弹"账号密码错误"） |
| 401 | 10002 | "账号或密码错误"（**后端不区分账号不存在/密码错，前端也别分**） |
| 403 | 10008 | "无权限访问"，停留在当前页 |
| 403 | 10013 | "账号已被禁用，请联系管理员" |
| 404 | 10007 | 邮箱未注册（邮箱验证码登录场景） |
| 409 | 10004 | "用户名或邮箱已被注册"，高亮对应输入框 |
| 409 | 10011 | 幂等键并发，提示"请求处理中，请稍后" |
| 423 | 10003 | 显示 `Retry-After` 秒数倒计时（"账号已锁定，请 14 分钟后再试"），按钮置灰 |
| 429 | 10010 | 显示 `Retry-After` 倒计时，禁用提交按钮 |
| 500/503 | 90000 | 通用错误提示；503 多为邮件服务不可用（本地检查 Mailpit 是否启动） |

`Retry-After` 在响应头里（`response.headers['retry-after']`），单位秒，最小 1。

---

## 10. 前端表单校验规则（和后端一致，先拦一道）

| 字段 | 规则 |
|---|---|
| `username` | 3–32 位，只允许字母、数字、下划线：`^[A-Za-z0-9_]{3,32}$` |
| `email` | 标准邮箱格式，后端会转小写后比对 |
| `password` / `new_password` | 8–32 位，**必须同时含字母和数字**，不允许空格 |
| `confirm_password` | 与上面完全一致 |
| `nickname` | ≤ 64 字，可空 |
| `agree_agreement` | 必须为 `true`，否则 `400 + 10000` |

密码强度不足时后端返回 `400 + 10000`，message 会说明缺哪类字符。

---

## 11. 联调最容易踩的四个坑

1. **路径还是旧的**：仓库里以前有 `/api/auth/*`，已全部删除，只保留 `/api/v1/auth/*`。
2. **只判断 `code` 不看 HTTP 状态**：423/429/409 时 HTTP 状态码也是 423/429/409，axios 会走 `catch`，`error.response.data.code` 才是业务码。
3. **注册按 200 判成功**：注册返回的是 **201**。
4. **不带 `Idempotency-Key`**：注册和重置密码不带就是 `400 + 10000`，不是网络问题。

## 12. 你可以独立开发的 Mock 约定

P3 前期不必等后端跑起来，按上面的响应结构自己 mock 即可，注意：

- 成功统一 `code: 0`，失败按第 9 节表给 `code` 与 HTTP 状态。
- 图形码 mock 一张固定图片 + 固定 `captcha_key`，登录时后端校验真实时再换。
- `permissions` mock `["chat:send"]`（学生）与 20 条全量（管理员）两套，用来验证按钮显隐。

后端起来后的真实自测序列（PowerShell）：

```powershell
# 1) 取图形验证码
Invoke-RestMethod http://localhost:8080/api/v1/auth/captcha | ConvertTo-Json -Depth 5

# 2) 发注册验证码（去 Mailpit http://localhost:8025 收信）
Invoke-RestMethod -Method Post http://localhost:8080/api/v1/auth/verification-codes `
  -ContentType "application/json" -Body '{"email":"student@example.com","purpose":"REGISTER"}'

# 3) 注册
Invoke-RestMethod -Method Post http://localhost:8080/api/v1/auth/register `
  -Headers @{ "Idempotency-Key" = [guid]::NewGuid().ToString() } `
  -ContentType "application/json" `
  -Body '{"username":"kaoyan_student","email":"student@example.com","verify_code":"<收到的码>","password":"KaoYan@2026","confirm_password":"KaoYan@2026","nickname":"考研小白","agree_agreement":true}'

# 4) 当前用户
Invoke-RestMethod http://localhost:8080/api/v1/auth/me -Headers @{ Authorization = "Bearer <token>" }
```
