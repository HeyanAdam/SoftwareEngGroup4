## 四、对 P1 的约定

1. **loginId 必须是用户主键**：`StpUtil.login(user.getId())`，不要用 username；否则 `StpInterfaceImpl` 查不到权限，全站 403。
2. **登录/当前用户接口请返回 `roles` + `permissions` 两个数组**（`AuthService.LoginResult` 已有该结构），P3 前端靠它做按钮显隐。
3. **`AuthService.resolveRegisterRole()` 现在找 `"ADMIN"`**：该角色码已不存在，实际效果是新注册用户一律是 `STUDENT`（符合接口文档 3.2「不允许首个注册用户自动成管理员」）。该段属 P2 任务 5，改动前会先与 P1 确认，不会单方面修改 `AuthService`。

## 五、对 P3 的约定

1. **按钮/菜单显隐用权限码判断**，不要按角色名硬编码（例如 `hasPerm('kb:view')`）。
2. **学生端只有 `chat:send`**：知识库、后台入口一律不显示（接口文档 11.5 禁止学生直接浏览知识库）。
3. **统一错误码处理**：
   - `401` + `10001` 未登录/过期 → 跳登录页
   - `403` + `10008` 无权限 → 提示无操作权限，不跳登录
   - `403` + `10009` 越权访问他人数据 → 提示无权访问
   - `429` + `10010` 限流；`423` + `10003` 账号锁定
4. 接口路径以接口文档 V1.1 为准：业务 `/api/v1/**`，后台 `/api/v1/admin/**`（该迁移属 P2 任务 7，尚未执行）。

### 8.5 鉴权链账号状态兜底（本次新增，`fc6c610`）

**漏洞**：Sa-Token 的已登录态存在 Redis，**登录之后不再查库**。`AdminService.updateStatus` 里的 `StpUtil.kickout` 只处理当前会话，多端登录或踢人失手时，被禁用的账号拿旧 Token 仍能继续调接口。

**修法**：

| 位置 | 改动 |
|---|---|
| `common/security/AccountStatusGuard.java`（新增） | 进程内缓存 60s 查 `sys_user.status`；`status==0` 抛 `ErrorCode.ACCOUNT_DISABLED`（403 + 10013）；查库异常 fail-open |
| `common/config/WebConfig.java` | `SaInterceptor` 的 `check()` 里 `StpUtil.checkLogin()` 之后接 `accountStatusGuard.ensureActive(...)` |
| `modules/admin/service/AdminService.updateStatus` | 三件套：`snapshotCache.evict` + `accountStatusGuard.evict` + `kickout` |
| `common/ErrorCode.java` | 新增常量 `ACCOUNT_DISABLED = 10013`，映射表字面量改常量引用 |
| `AccountStatusGuardTest`（新增 6 例） | 禁用拒绝 / 正常放行 / 账号不存在按禁用 / 查库异常放行 / 缓存命中和 evict / null 不查库 |

**真机验证（`tools/p2-guard-check.ps1`，绕开 kickout 直改库）**：

```
学生 id=2，基线 /auth/me -> 200
直接改库 status=0（不踢人、不清缓存）
第 1~20 次（0~57s）：200      ← 状态缓存未过期
第 21 次（60s）：403 + 10013  ← 鉴权链拦住旧 Token
走后台接口改回 status=1 -> code=0，随后 /auth/me 恢复 200
```

> 结论：这条 403 与 `kickout` 无关（会话没被动过），证明"踢人失手也挡得住"。正常后台禁用路径会主动 `evict`，**立即生效**；只有绕过服务直改库才有最长 60s 窗口。

### 8.7 四个错误码的真机触发路径（答辩演示顺序）

| 业务码 | HTTP | 触发方式 | 真机可演示 |
|---|---|---|---|
| `10001` 未登录/过期 | 401 | 不带 Token 或删掉 Token 访问任意受保护接口（如 `/api/kb`） | ✅ |
| `10008` 无接口权限 | 403 | 学生 Token 调 `GET /api/admin/users`（缺 `admin:user:list`） | ✅ |
| `10013` 账号禁用 | 403 | ① 管理员 `PUT /api/admin/users/{id}/status` 置 0 后再登录；② 旧 Token 在踢人未生效时被鉴权链拦住 | ✅ |
| `10009` 越权访问数据 | 403 | 需业务接口先调用 `DataScopeService.requireSelf()`；**当前零调用点**，无真机路径 | ⏸ 前端用 DEV `?code=10009` 预览 |

> 10009 的处理已与 P3 约定：**本期不接代码**，用 `if (import.meta.env.DEV)` 包住的 `?code=` 隐藏入口预览 403 页样式；接真实接口放到答辩后。

### 8.8 环境降级说明（MinIO / Milvus 默认不启用）

启动时会出现两条 WARN，属预期降级，不影响认证与 RBAC 验收：

| 组件 | 现象 | 原因 | 影响 |
|---|---|---|---|
| MinIO | `MinIO 初始化失败，文件功能暂不可用` | `deploy/docker-compose.yml` 默认不启 minio；本机 `docker pull` 任何 registry 均 `denied`，根因是 Docker 走内置代理 `docker.internal:3128` | 文件上传/下载不可用，其余功能正常 |
| Milvus | `Milvus ... DEADLINE_EXCEEDED` | compose 无 milvus，且 `.env` 里 `LLM_API_KEY`/`EMBEDDING_API_KEY` 仍是占位符 | 向量检索不可用，RBAC 不受影响 |

`deploy/README.md` 已写明：默认四服务（mysql/redis/rabbitmq/mailpit）、MinIO 与 Milvus 的启用三步、以及 `doc_chunk` 维度必须等于 `EMBEDDING_DIMENSION=1024`。
