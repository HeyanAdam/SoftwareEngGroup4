## 二、真机复现命令（PowerShell 5.1，路径已按 `/api/v1` 迁移）

```powershell
# 0. 前提：后端已重启（路径改动不热生效）、MySQL/Redis 就绪
cd D:\SoftwareEngGroup4\backend

# 1. 登录拿 Token（登录需要图形码，脚本已封装，手工验证时可直接用测试账号）
$admin = (Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/auth/login `
  -ContentType 'application/json' -Body '{"login_type":"PASSWORD","account":"admin","password":"Admin@123456","captcha_key":"...","captcha_code":"..."}').data
$h = @{ Authorization = "Bearer $($admin.token)" }

# 2. V1：无 Token → 401 + 10001
Invoke-WebRequest -Uri http://localhost:8080/api/v1/admin/users -SkipHttpErrorCheck | Select-Object StatusCode, Content

# 3. V2：伪造 Token → 401 + 10001
Invoke-WebRequest -Uri http://localhost:8080/api/v1/admin/users -Headers @{ Authorization = 'Bearer fake-token' } -SkipHttpErrorCheck | Select-Object StatusCode, Content

# 4. V3：学生 Token 调后台 → 403 + 10008
Invoke-WebRequest -Uri http://localhost:8080/api/v1/admin/users -Headers @{ Authorization = "Bearer $($stu.token)" } -SkipHttpErrorCheck | Select-Object StatusCode, Content

# 5. V4：用 B 的 Token 读 A 的会话 → 403 + 10009（会话不存在才是 404）
Invoke-WebRequest -Uri http://localhost:8080/api/v1/chat/conversations/<A的会话id>/messages -Headers @{ Authorization = "Bearer $($stuB.token)" } -SkipHttpErrorCheck | Select-Object StatusCode, Content

# 6. V7：解绑唯一管理员 → 业务拒绝
Invoke-WebRequest -Method Delete -Uri "http://localhost:8080/api/v1/admin/users/1/roles/5" -Headers $h -SkipHttpErrorCheck | Select-Object StatusCode, Content
```

> 一键跑全部自动用例：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\p2-acceptance.ps1`
> 兜底验证（10013）：`powershell -NoProfile -ExecutionPolicy Bypass -File tools\p2-guard-check.ps1`

## 三、为什么 10009 现在能真机触发（本轮改动关键）

改造前 `ChatService` 对"会话不存在"和"会话不属于你"一律抛 `new BizException(404, "会话不存在")`，验收脚本里 10009 那条只能挂 SKIP。本轮改为：

| 情形 | 返回 |
|---|---|
| 会话不存在 / 已逻辑删除 | HTTP 404 + code 404 |
| 会话存在但不是当前用户的（且当前用户无 `ALL` 数据范围） | HTTP 403 + code **10009** |
| 当前用户是 `SYSTEM_ADMIN`（`ALL` 范围） | 放行 |

判定走 `DataScopeService#canAccess(ownerUserId)`：本人直接放行，`ALL` 范围放行，其余 10009。这条改动同时满足任务 3「资源详情校验归属」与任务 7「Service 调用数据范围服务」。
