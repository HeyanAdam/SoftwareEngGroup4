## 4. 步骤 E1：Redis 缓存

Key：

```text
admin:dashboard:summary:v1:{days}
```

TTL：

```text
15 seconds
```

Value：

```text
AdminDashboardSummaryVO JSON
```

流程：

1. 校验 `days`。
2. 读取 Redis。
3. 命中则反序列化返回。
4. 未命中则执行统计。
5. 写入 Redis。
6. Redis 异常时跳过缓存，直接返回统计。

禁止：

- `KEYS *`
- 把完整聊天正文或邮箱写入缓存
- 没有 TTL 的永久 key

### 测试

- 命中不调用统计服务。
- TTL 过期后再统计。
- Redis 不可用时接口仍成功。
- 不同 `days` 使用不同 key。

## 5. 步骤 E2：RabbitMQ 队列指标

使用 Spring `RabbitAdmin#getQueueInfo`，不要从前端访问 RabbitMQ。

统计：

```text
docParseReady
docParseConsumers
docParseDlq
```

队列：

```text
kaoyan.doc.parse.queue
kaoyan.doc.parse.dlq
```

规则：

- 消息数取 `queueCount`。
- 消费者数取 `consumerCount`。
- 队列查询异常时返回 `rabbitmq = DOWN` 和安全的 0 值。
- 不记录 RabbitMQ 管理密码到日志。

## 6. 步骤 E3：Outbox 指标

在 `OutboxMapper` 增加：

```text
countByStatus
countStuckPublishing
```

统计：

```text
PENDING
RETRY_WAIT
FAILED
PUBLISHING 超过 5 分钟
```

DTO 中：

```text
outboxPending = PENDING + RETRY_WAIT
outboxFailed = FAILED + stuckPublishing
```

不能读取 payload 正文。

## 7. 步骤 E4：系统健康指标

抽出一个服务：

```text
SystemHealthMetricsService
```

返回：

- MySQL `UP/DOWN`
- Redis `UP/DOWN`
- RabbitMQ `UP/DOWN`

复用现有 `HealthController` 的连接检查思路，但不要让大屏一边聚合业务数据、一边在 Controller 里重复拼探活逻辑。

超时控制：

- 单项探活不超过 2 秒。
- 一项 DOWN 不影响其他两项返回。
- 失败日志只写异常摘要。

## 8. 步骤 E5：集成到大屏 Service

与后端统计负责人约定 provider：

```java
public interface DashboardSummaryProvider {
    AdminDashboardSummaryVO buildBusiness(int days);
}
```

大屏最终 Service：

```text
缓存读取
  -> 业务统计
  -> 系统指标
  -> DTO 组装
  -> 缓存写入
```

不要在 RabbitMQ 或 Redis 故障时让整个接口 500。

## 10. 步骤 E7：真实环境浏览器验收

先确认：

```powershell
docker compose ps
Invoke-RestMethod http://localhost:8080/api/v1/health/ready
docker exec kaoyan-rabbitmq rabbitmqctl -q list_queues name messages_ready messages_unacknowledged consumers
```

使用管理员登录：

1. 打开 `/admin/dashboard`。
2. KPI 与 SQL 查询一致。
3. 队列数字与 `rabbitmqctl list_queues` 一致。
4. 停止 Redis：

```powershell
docker stop kaoyan-redis
```

预期：

- 服务状态变红。
- 大屏仍能展示数据库业务数据。
- 不出现无限 loading。

5. 启动 Redis：

```powershell
docker start kaoyan-redis
```

预期：

- 下一次轮询自动恢复。

6. 停止 RabbitMQ：

```powershell
docker stop kaoyan-rabbitmq
```

预期：

- RabbitMQ 状态变红。
- 用户、文件、聊天统计仍可显示。

7. 恢复 RabbitMQ。

8. 检查 15 秒轮询、页面隐藏暂停、全屏和手动刷新。

## 11. 步骤 E8：权限越权验收

- 未登录访问大屏接口：401。
- 学生访问大屏接口：403 + 10008。
- `DATA_AUDITOR`：只读可用。
- `SYSTEM_ADMIN`：可用。
- 前端直接输入 `/admin/dashboard`：无后台会话时跳 `/admin/login`。

## 12. 步骤 E9：性能检查

- 冷启动一次聚合接口 < 1 秒。
- Redis 命中 < 200 毫秒。
- 连续刷新 10 次不会持续增加数据库慢查询。
- 抓取 SQL `EXPLAIN`，确认没有全表扫描。
- 不执行 `SELECT *`。
