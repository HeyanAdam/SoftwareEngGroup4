## 1. 命名规则（与接口文档一致）

| 项 | 规则 |
|---|---|
| 格式 | `module:action` |
| `module` | 与接口路径的资源名一致：`/api/v1/study-plans` → `study-plan`，`/api/v1/knowledge-bases` → `kb` |
| `action` | `view` / `create` / `update` / `delete` / `upload` / `download` / `send` / `manage` |
| 后台资源例外 | 后台管理域采用三段式 `admin:资源:操作`，如 `admin:user:list`、`admin:role:update`；其中 `list` 为后台专用动作，不列入上方动作清单 |
| 示例 | `study-plan:view`、`file:upload`、`admin:user:list` |
| 兼容性 | main 分支 V6 已上线的 11 条权限码**一个都不改**，新增权限码按本规则追加 |

> 为什么不用 docx 里的 `studyplan:add`：本项目接口路径是 `study-plans`（带中划线、复数），权限码跟着路径走才能在代码里一一对上；
> 且 main 分支已经落库了 11 条 `kb:view` 这类写法，改名会和已合并的 V6 冲突。

**数据范围说明**

- `ALL`：可读全部数据（管理员、内容运营）。

## 5. 数据写入方式（已确认：启动幂等补齐）

当前分支的写入由 `RbacInitializer` 承担，规则如下：

- 权限字典只补缺：`sys_permission` 中没有的权限码才插入，已存在的不改名、不改排序。
- 普通角色只在首次创建时写默认授权；已存在则完全沿用库里的授权，后台删掉的授权重启不会长回来。
- `SYSTEM_ADMIN` 是内置全权角色，每次启动以 `INSERT IGNORE` 补齐全部权限码，只增不删，避免新增权限上线后老库管理员突然 403。
- 旧角色码 `ADMIN` / `KB_ADMIN` / `DATA_VIEWER` 在启动时自动迁移到官方角色码并删除。

不采用「V6 唯一写入 + initializer 只校验」的校验式：权限码由 11 条扩到 20 条后，校验式会因数量不一致直接终止启动，反而挡住老库升级。

下列 V7 迁移草案仅在后续改走 Flyway 迁移式时使用，当前分支不执行。

```sql
-- V7__extend_rbac_business_permissions.sql
-- 仅新增 9 条业务权限码，不改 V6 既有 11 条，不改任何已上线角色的既有授权。

INSERT INTO sys_permission (perm_code, perm_name, perm_type, parent_id, path, sort)
VALUES
  ('study-plan:view',   '查看学习计划', 'API', 0, NULL, 120),
  ('study-plan:create', '生成学习计划', 'API', 0, NULL, 130),
  ('study-plan:update', '调整学习计划', 'API', 0, NULL, 140),
  ('study-task:update', '更新任务状态', 'API', 0, NULL, 150),
  ('question:view',     '浏览题库',     'API', 0, NULL, 160),
  ('file:view',         '文件列表',     'API', 0, NULL, 170),
  ('file:upload',       '上传文件',     'API', 0, NULL, 180),
  ('file:download',     '下载文件',     'API', 0, NULL, 190),

AS seed
ON DUPLICATE KEY UPDATE
```

## 6. 与 main 分支现有实现的差异（已对齐的部分见下表）

| # | 项 | main 分支现状 | 本分支现状 | 处理 |
|---|---|---|---|---|
| 1 | 建表方式 | Flyway `db/migration`，`db/schema.sql` 已删除 | 本地副本仍为 `db/schema.sql`、无 migration 目录 | 以 main 的 migration 为准，本地先 `git pull` 再改，避免冲突 |
| 2 | RBAC 写入 | V6 写入 11 条，`RbacInitializer` 只校验不写库 | `RbacInitializer` 幂等写入，只补缺 | 已确认采用写入式，理由见第 5 节 |
| 3 | 权限条数 | 11 | 20（多 9 条扩展权限） | 扩展 9 条由 initializer 补齐；如后续改迁移式，按第 5 节草案 |
| 4 | 角色码 | `SYSTEM_ADMIN` / `STUDENT` / `CONTENT_OPERATOR` / `DATA_AUDITOR` | 已统一为官方四个角色码，旧码启动自动迁移 | 已对齐，代码中不再出现 `ADMIN` / `KB_ADMIN` / `DATA_VIEWER` |
| 5 | 首个注册用户 | `AuthService` 在 `SYSTEM_ADMIN` 下无用户时绑定为首个管理员 | `AuthService` 仍按 `ROLE_ADMIN = "ADMIN"` 查找，该码不存在，故新注册用户一律为 `STUDENT` | 符合接口文档 3.2；如需恢复「首用户为管理员」，先与 P1 确认再改 |
