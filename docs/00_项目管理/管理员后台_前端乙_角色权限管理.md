# 管理员后台前端（乙）：角色权限、字典与日志

> 参考资料：《后台管理员登录与角色权限分配——设计与实施步骤》
> 目标：负责禅道风格后台的核心角色权限页，以及权限字典和登录日志页。
> 说明：本文是乙个人的独立操作文档。甲负责登录、壳层和用户管理，乙可以与甲并行开发。

## 1. 乙的交付范围

乙负责：

- 管理端 TypeScript 类型和 API 封装。
- 角色列表、角色统计、新建、编辑、删除。

乙不负责：

- 用户启停和用户角色抽屉。
- 数据大屏统计和图表。

## 2. 与甲的接口约定

开工前与甲确认：

- 后台请求函数为 `adminGet/adminPost/adminPut/adminDel`。
- Token 为 `sa_admin_token`。
- 后台准入按任意 `admin:*` 权限，不按 `SYSTEM_ADMIN` 硬编码。
- 甲负责 `/admin/roles`、`/admin/permissions`、`/admin/logs` 的路由占位。
- 乙负责这三个路由对应的内容组件。
- `AdminLayout` 菜单由甲提供，乙不直接修改甲的文件。

接口前缀：

```text
/api/v1/admin
```

角色相关权限：

```text
admin:role:list    查看角色、权限、日志
admin:role:update  新建/编辑/删除角色、保存角色授权
```

## 5. 步骤 B2：权限模块工具

新增：

```text
frontend/src/features/admin/roles/components/permissionModules.ts
frontend/src/features/admin/roles/components/permissionModules.spec.ts
```

不要按 `sort` 数字区间分组。现有数据库中存在旧排序和交叉排序。

使用权限码前缀：

```ts
const MODULE_BY_PREFIX: Record<string, string> = {
  'study-plan': '督学陪伴',
  'study-task': '督学陪伴',
  question: '刷题训练',
  file: '文件存储',
  kb: '知识库',
  doc: '知识库',
  chat: 'AI 对话',
  admin: '后台管理',
}

export function moduleOfPermission(code: string): string {
  return MODULE_BY_PREFIX[code.split(':')[0]] ?? '其他权限'
}
```

分组稳定顺序：

```text
督学陪伴
刷题训练
文件存储
知识库
AI 对话
后台管理
其他权限
```

工具函数至少覆盖：

- `groupPermissions`
- `groupSelectionState`
- `toggleGroup`
- `permissionCodesToIds`

## 7. 步骤 B4：权限矩阵

新增 `PermissionMatrix.vue`。

### 7.1 结构

每个模块一个卡片：

```text
模块名 (已选/总数)        [全选复选框]
权限名称  权限码          [复选框]
```

### 7.2 全选与半选

`indeterminate` 只用于：

```text
已选数量 > 0 && 已选数量 < 总数
```

### 7.3 只读规则

`SYSTEM_ADMIN`：

- 显示全部 20 项。
- 全部选中。
- 全部禁用。
- 隐藏保存按钮。
- 顶部提示“全权角色由系统自动补齐全部权限”。

其他角色：

- 根据权限码映射到权限 ID。
- 允许勾选。
- 显示未保存标记。

### 7.4 切换角色

如果当前角色存在未保存修改：

```text
ElMessageBox.confirm('当前修改未保存，是否放弃？')
```

用户取消则保持当前角色。

## 8. 步骤 B5：角色表单

### 新建

- `roleCode`

- `description`

校验：

```regex
^[A-Z][A-Z0-9_]{2,31}$
```

### 编辑

只允许修改：

- 角色名称

### 删除

- 二次确认。
- 内置角色禁止删除。
- 有用户绑定时展示后端错误。

## 9. 步骤 B6：核心角色权限页

新增 `AdminRolesPage.vue`。

页面布局：

```text
左栏：角色列表
中栏：权限矩阵
右栏：已选数量、保存、重置
```

加载顺序：

1. 加载角色汇总。
2. 加载全部权限。
3. 加载第一个可读角色的权限码。
4. 建立 `code -> permission`
5. 建立 `id -> permission`

保存：

```http
PUT /admin/roles/{id}/permissions
{"ids":[permissionId...]}
```

成功后：

- 更新本地权限数组。
- 更新角色卡片的权限数。
- 清除未保存状态。
- 显示“保存成功，相关账号下一次请求即生效”。

失败：

- 保留当前勾选。
- 展示 `ApiError.message`。
- `10008` 显示无授权权限。

重置：

- 重新拉取该角色权限码。
- 恢复当前角色的选择。

权限控制：

- 查看需要 `admin:role:list`。
- 保存和角色增删改需要 `admin:role:update`。
- 没有 update 权限时隐藏或禁用写按钮。
