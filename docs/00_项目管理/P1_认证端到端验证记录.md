## 3. 本轮发现并修复的缺陷

### 3.1 邮箱验证码完全发不出去（阻断级）

- 现象：`POST /verification-codes` 返回 200，但 Mailpit 收件箱 0 封；日志报 `Invalid bound statement (not found): com.group4.kaoyan.modules.auth.service.EmailSender.sendVerificationCode`。
- 根因：`KaoyanApplication` 的 `@MapperScan("com.group4.kaoyan.modules")` 按包扫描，把业务接口 `EmailSender` 也注册成了 MyBatis Mapper 代理，`EmailCodeService` 注入到的是代理而不是 `SmtpEmailSender`。
- 修复：改为 `@MapperScan(value = "com.group4.kaoyan.modules", annotationClass = Mapper.class)`，只扫带 `@Mapper` 的接口（11 个 Mapper 均已标注）。
- 说明：该缺陷单元测试不可见，因为测试把 `EmailSender` mock 掉了。

### 3.2 服务端异常错误返回 HTTP 200

- 现象：未处理异常返回 `HTTP 200 + {"code":90000}`，违反《接口设计文档 V1.1》2.1「90000 → 500」。
- 修复：`GlobalExceptionHandler` 兜底改 500；Bean Validation 改 400 + 10000；`BizException` 按错误码映射状态（10001/10002→401、10003→423、10004/10011→409、10007→404、10008/10009/10013→403、10010→429、10000/10005/10006/10012→400、其余 500）。

### 3.3 发码接口耗时 20.9 秒

- 现象：邮件确实发到 Mailpit，但 HTTP 响应要等 20–30 秒。
- 定位：thread dump 命中 `MimeMessage.updateMessageID → UniqueValue → InternetAddress.getLocalHostName → InetAddress.getCanonicalHostName → Inet6AddressImpl.getHostByAddr`，即生成 Message-ID 时做反向 DNS，Windows 上阻塞约 20 秒。
- 修复：`spring.mail.properties.mail.from` 显式给 `no-reply@kaoyan.local`，跳过反向解析；另补 `mail.smtp.localhost` 与连接/读/写超时各 5 秒作为第二道保险。
- 效果：改前 20931ms，改后预热后单次 206ms；本次全流程各次发码 2069–2591ms，为每次新建 SMTP 连接的固定开销。
