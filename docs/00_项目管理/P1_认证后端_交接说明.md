## 3. 接口清单

| 方法 | 路径 | 匿名 | 幂等 | 说明 |
|---|---|---|---|---|
| GET | `/api/v1/auth/captcha` | 是 | 天然 | `captcha_key` + `image_base64` + `expires_in` |
| POST | `/api/v1/auth/verification-codes` | 是 | — | `purpose`：`REGISTER` / `EMAIL_LOGIN` / `RESET_PASSWORD` |
| POST | `/api/v1/auth/register` | 是 | 需 `Idempotency-Key` | 成功 **201** |
| POST | `/api/v1/auth/login` | 是 | — | `login_type`：`PASSWORD` / `EMAIL_CODE` |
| GET | `/api/v1/auth/me` | 否 | 天然 | 账号、`email_masked`、角色、权限、`has_profile` |
| POST | `/api/v1/auth/logout` | 否 | 天然 | 吊销当前 Token |
| POST | `/api/v1/auth/password-reset` | 是 | 需 `Idempotency-Key` | 成功后该用户所有旧 Token 失效 |

登录响应 `data`：

```json
{
  "token": "sa-token-value",
  "token_type": "Bearer",
  "expires_in": 2592000,
  "user_id": 10001,
  "username": "kaoyan_student",
  "nickname": "考研小白",
  "roles": ["STUDENT"],
  "permissions": ["chat:send"],
  "has_profile": false
}
```

> `roles` / `permissions` 与 `@SaCheckPermission` 读的是**同一份** `RbacSnapshotCache`，
> 不会出现「前端说有权限、后端 403」的口径不一致。

## 4. Redis Key 设计

| Key | 写入方 | TTL | 用途 |
|---|---|---|---|
| `auth:captcha:{key}` | CaptchaService | 5 分钟 | 图形验证码答案 |
| `auth:captcha:fail:{key}` | CaptchaService | 5 分钟 | 输错计数，≥3 作废 |
| `auth:code:{purpose}:{email}` | EmailCodeService | 5 分钟 | 邮箱验证码（6 位，一次性） |
| `auth:code:send:email:{purpose}:{email}` | EmailCodeService | 60 秒 | 同邮箱重发间隔 |
| `auth:code:send:ip:{ip}` | EmailCodeService | 60 秒 | 同 IP 重发间隔 |
| `auth:code:fail:{purpose}:{email}` | EmailCodeService | 5 分钟 | 输错计数，≥5 作废 |
| `auth:login:fail:{account}` | LoginAttemptService | 30 分钟 | 连续失败计数 |
| `auth:login:lock:{account}` | LoginAttemptService | 15 分钟 | 锁定标记 |
| `auth:login:fail:ip:{ip}` | LoginAttemptService | 30 分钟 | 同 IP 失败计数 |
| `auth:rate:{action}:{identity}` | AuthRateLimitService | 1 分钟 / 1 小时 | 固定窗口限流 |

限流口径：`captcha` 30/分钟/IP；`login` 20/分钟/IP；`register` 20/小时/IP；`password-reset` 10/小时/IP；验证码邮件 10 封/小时/IP + 60 秒间隔。

## 5. 错误码与 HTTP 状态（与接口文档 2.1 逐条对齐）

| code | HTTP | 场景 |
|---|---|---|
| 10000 | 400 | 参数校验、密码强度、协议未勾选、缺 `Idempotency-Key` |
| 10001 | 401 | 未登录 / Token 失效（含全局 `NotLoginException`） |
| 10002 | 401 | 账号或密码错误（不区分账号不存在） |
| 10003 | 423 | 连续失败锁定（带 `Retry-After`） |
| 10004 | 409 | 用户名或邮箱已存在 / 唯一键冲突 |
| 10005 | 400 | 图形/邮箱验证码错误、过期、超次数 |
| 10006 | 400 | 两次密码不一致 |
| 10007 | 404 | 用户不存在（邮箱登录 / 重置密码） |
| 10008 | 403 | 无接口访问权限（缺权限码或角色） |
| 10009 | 403 | 无权访问该数据（P2 数据范围使用，常量已登记） |
| 10010 | 429 | 限流（带 `Retry-After`） |
| 10011 | 409 | 同一幂等键并发提交 |
| 10012 | 400 | 请求类型不受支持（按文档口径用 400，不用 405） |
| **10013** | **403** | **账号已被禁用**（文档缺此项，见第 10 节） |
| 90000 | 500 / 503 | 服务器内部异常；依赖不可用（邮件发不出去时用 503 + 90000） |

## 6. 与 P2 的合流结果

1. **权限字典与角色矩阵已生效**：`sys_permission` 由 `RbacInitializer` 启动补齐到 20 条，
   4 个内置角色 `SYSTEM_ADMIN(20) / CONTENT_OPERATOR(6) / DATA_AUDITOR(3) / STUDENT(1)`，
   旧角色码 `ADMIN / KB_ADMIN / DATA_VIEWER` 启动时自动迁移。
2. **鉴权链路**：`StpUtil.login(userId)` → `StpInterfaceImpl` → `RbacSnapshotCache`（TTL 5 分钟）→
   `AdminService.assignRoles/assignPermissions` 主动失效，改完权限下次请求即生效。
3. **登录/`me` 返回的角色权限与鉴权同源**（同一份快照），P3 可以放心用 `permissions` 做按钮显隐。
4. **注册不再产生管理员**：固定绑 `STUDENT`，与接口文档 3.2 和 P2 交付说明一致。
5. **`SessionService` 已交给 P2 复用**：`logoutUser(userId)` 用于禁用/降权/改密后踢人。

## 7. 给 P3 的接口契约

- 字段一律 `snake_case`；认证接口响应固定 `application/json`。
- 密码登录：`login_type=PASSWORD` + `account/password/captcha_key/captcha_code`；
  邮箱登录：`login_type=EMAIL_CODE` + `email/verify_code`。
- `GET /auth/captcha` 的 `image_base64` 已带 `data:image/png;base64,` 前缀，可直接塞 `img.src`。
- `register` / `password-reset` 必须带 `Idempotency-Key`（UUID 即可），否则 400 + 10000。
- 423 / 429 都带 `Retry-After`（秒），按该值禁用按钮倒计时。
- 401 + 10001 跳登录；403 + 10008 提示无权限不跳转；403 + 10009 提示无权访问；403 + 10013 提示账号被禁用。
- `has_profile=false` 时跳画像引导页。

## 10. 遗留问题与风险

1. **「账号已被禁用」没有官方错误码**：接口文档 2.1 只到 10012，P1 取 **10013（403）**。
   需文档负责人确认后同步给 P3；若要改，只改 `AuthErrorCode.ACCOUNT_DISABLED` 一处。
2. **`sys_user.email` 无唯一索引**：靠应用层小写查重 + 唯一键冲突兜底 409/10004。
   并发注册同一邮箱仍可能双写，建议数据库同学加 `V7__unique_user_email.sql`
   （`ALTER TABLE sys_user ADD UNIQUE KEY uk_user_email (email);`，执行前先清理重复数据，否则迁移会失败）。
3. **旧 `/api/auth/*` 已删除**：P3 登录页必须切到 `/api/v1/auth/*`，否则联调期 404。
4. **幂等记录无清理任务**：`sys_idempotency_record` 有 `expires_at`（24h）但没有删除过期行的作业，数据量小可后续加。
5. **Sa-Token 仍是内存 Dao**：仓库没有 `sa-token-redis`，服务重启后会话丢失。接入后 `SessionService` 语义不变。
6. **响应类型的历史坑**：工程同时含 `jackson-dataformat-xml`，未指定 `Accept` 时会协商成 XML。
   认证接口已用 `produces=application/json` 锁死；其它模块建议在 platform 层加全局默认 JSON（P2 范围）。
7. **P2 的 zip 基于旧版 main**：其 `pom.xml` 删掉了 Flyway 与 lombok 1.18.38 覆盖、`KaoyanApplication` 删了 MinIO 配置、
   `KnowledgeService/RagChatService/RetrievalService` 把角色校验退化成写死的 `"ADMIN"`。
   本次合并**只取 P2 的 RBAC 成果**，这些文件保留 main 版本。请 P2 推送时确认自己的分支是从最新 main 拉出来的。
8. **`/api/kb/**` 仍是匿名白名单**（原仓库遗留）：属 P2 任务 7，本次未动。
9. **README 过时**：`backend/README.md` 的「谁先注册谁是管理员」「`/api/auth/*`」描述已失效，建议集成分支统一更新。
