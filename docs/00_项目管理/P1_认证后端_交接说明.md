## 3. 接口清单

| 方法 | 路径 | 是否匿名 | 幂等 | 说明 |
|---|---|---|---|---|
| GET | `/api/v1/auth/captcha` | 是 | 天然 | 返回 `captcha_key` + `image_base64` + `expires_in` |
| POST | `/api/v1/auth/verification-codes` | 是 | — | `purpose`：`REGISTER` / `EMAIL_LOGIN` / `RESET_PASSWORD` |
| POST | `/api/v1/auth/register` | 是 | 需要 `Idempotency-Key` | 成功返回 **201** |
| POST | `/api/v1/auth/login` | 是 | — | `login_type`：`PASSWORD` / `EMAIL_CODE` |
| GET | `/api/v1/auth/me` | 否 | 天然 | 账号、角色、权限、`has_profile` |
| POST | `/api/v1/auth/logout` | 否 | 天然 | 吊销当前 Token |
| POST | `/api/v1/auth/password-reset` | 是 | 需要 `Idempotency-Key` | 成功后该用户所有旧 Token 失效 |

登录成功响应（`data`）：

```json
{
  "token": "sa-token-value",
  "token_type": "Bearer",
  "expires_in": 2592000,
  "user_id": 10001,
  "username": "kaoyan_student",
  "nickname": "考研小白",
  "roles": ["STUDENT"],
  "permissions": ["chat:send"],
  "has_profile": false
}
```

## 4. Redis Key 设计（与分工文档逐条对齐）

| Key | 写入方 | TTL | 用途 |
|---|---|---|---|
| `auth:captcha:{captcha_key}` | CaptchaService | 5 分钟 | 图形验证码答案 |
| `auth:captcha:fail:{captcha_key}` | CaptchaService | 5 分钟 | 输错计数，≥3 作废 |
| `auth:code:{purpose}:{email}` | EmailCodeService | 5 分钟 | 邮箱验证码（6 位数字，一次性） |
| `auth:code:send:email:{purpose}:{email}` | EmailCodeService | 60 秒 | 同邮箱同用途重发间隔 |
| `auth:code:send:ip:{ip}` | EmailCodeService | 60 秒 | 同 IP 重发间隔 |
| `auth:code:fail:{purpose}:{email}` | EmailCodeService | 5 分钟 | 输错计数，≥5 作废 |
| `auth:login:fail:{account}` | LoginAttemptService | 30 分钟 | 连续失败计数 |
| `auth:login:lock:{account}` | LoginAttemptService | 15 分钟 | 锁定标记 |
| `auth:login:fail:ip:{ip}` | LoginAttemptService | 30 分钟 | 同 IP 失败计数 |
| `auth:rate:{action}:{identity}` | AuthRateLimitService | 1 分钟 / 1 小时 | 固定窗口限流 |

限流口径：`captcha` 30 次/分钟/IP；`login` 20 次/分钟/IP；`register` 20 次/小时/IP；`password-reset` 10 次/小时/IP；验证码邮件 10 封/小时/IP + 60 秒间隔。

## 5. 错误码与 HTTP 状态

| code | HTTP | 场景 |
|---|---|---|
| 10000 | 400 | 参数校验、密码强度、协议未勾选、缺 `Idempotency-Key` |
| 10002 | 401 | 账号不存在 / 密码错误（统一提示） |
| 10003 | 423 | 连续失败锁定（带 `Retry-After`） |
| 10004 | 409 | 用户名或邮箱已存在 / 唯一键冲突 |
| 10005 | 400 | 图形验证码或邮箱验证码错误、过期、超次数 |
| 10006 | 400 | 两次密码不一致 |
| 10007 | 404 | 用户不存在（邮箱验证码登录 / 重置密码） |
| 10008 | 403 | 账号被禁用（**见第 10 节说明**） |
| 10010 | 429 | 限流（带 `Retry-After`） |
| 10011 | 409 | 同一幂等键并发提交，前一次仍在处理 |
| 10012 | 405 | HTTP 方法不支持 |
| 90000 | 503 | 邮件服务不可用 / 发信失败 |

> 认证接口的 HTTP 状态由 `AuthExceptionHandler`（`assignableTypes = AuthController.class`）就地映射，
> 与 P2 的全局 `GlobalExceptionHandler` 互不覆盖。

## 6. 给 P2 的复用接口

1. **会话吊销**（`modules/auth/service/SessionService`）
   - `logoutCurrentSession()` 退出当前 Token；
   - `logoutUser(userId)` 吊销该用户全部 Token（密码重置、禁用用户、管理员重置都用它）；
   - `isUserLoggedIn(userId)` 判断是否还有有效会话。
2. **权限快照**（`AuthService.rolesOf(userId)` / `permissionsOf(userId)`），数据来自 `RoleMapper` / `PermissionMapper`，与 `StpInterfaceImpl` 一致。
   P1 未改动 `StpInterfaceImpl`，RBAC 查询、缓存、数据范围仍是 P2 的范围。
3. **匿名接口清单**（`WebConfig.PUBLIC_PATHS`）：captcha、verification-codes、register、login、password-reset、`/api/v1/health/**`。
4. **注册不再自动产生管理员**：一律绑定 `STUDENT`。管理员必须走 P2 的受控初始化（环境变量/初始化命令），
   `sys_role_permission` 种子不需要改。
5. **登录日志表已用起来**：成功/失败都写 `sys_login_log`（账号、结果、IP、UA、失败原因），P2 做审计时可直接查。

## 7. 给 P3 的接口契约

- 字段一律 `snake_case`，时间 0 处（本模块不返回时间字段）。
- 账号密码登录：`login_type=PASSWORD`，必填 `account`、`password`、`captcha_key`、`captcha_code`。
- 邮箱验证码登录：`login_type=EMAIL_CODE`，必填 `email`、`verify_code`。
- 验证码：`GET /auth/captcha` 返回 `image_base64`（已是 `data:image/png;base64,` 前缀，可直接塞 `img.src`）。
- `register` / `password-reset` 必须带 `Idempotency-Key` 请求头（UUID 即可），否则 400 + 10000。
- 423 与 429 都会带 `Retry-After`（秒），请按该值倒计时禁用按钮。
- Token 放 `Authorization: Bearer <token>`；`expires_in` 单位是秒（默认 30 天）。
- 登录成功要按 `has_profile` 决定是否跳画像引导页。

| 现有业务接口加权限注解 | P2 任务 7 |
| `BaseEntity` / `PageQuery` / `PageResult` / `MyMetaObjectHandler` | 本模块实体是既有表映射，未引入公共父类，等 platform-deps 合并后再统一 |
| 全局 Jackson `snake_case` | 本模块所有 DTO/VO 已用 `@JsonNaming(SnakeCaseStrategy)` 自保；P2 加全局配置后依然兼容，不会双重转换 |

**依赖说明（合并注意事项）**

1. `pom.xml` 的 `spring-boot-starter-mail` 与 `application.yml` 的 `spring.mail` 段，P2 的 `chore/platform-deps` 也会加，
   合并时**保留一份**即可，两边内容一致。
2. P1 只用了 `StringRedisTemplate` 默认 Bean，没有自定义 Redis 配置；P2 的 Redis 公共配置（序列化器、`sa-token-redis`）合并后不需要改本模块代码。
3. 当前 `sa-token` 仍是默认内存 Dao（仓库里没有 `sa-token-redis` 依赖），**服务重启后会话丢失**。接上 `sa-token-redis` 后 `SessionService` 语义不变，无需改代码。

## 9. 本地验证步骤

```powershell
cd deploy
Copy-Item .env.example .env      # 首次
docker compose up -d mysql redis mailpit
cd ..\backend
mvn test
mvn -DskipTests package
```

启动后打开 `http://localhost:8080/swagger-ui/index.html`，或按下面顺序手工验证（Mailpit 收信页 `http://localhost:8025`）：

```powershell
# 1. 图形验证码
curl.exe -s http://localhost:8080/api/v1/auth/captcha

# 2. 发送注册验证码（去 Mailpit 取 6 位码）
curl.exe -s -X POST http://localhost:8080/api/v1/auth/verification-codes `
  -H "Content-Type: application/json" `
  -d '{\"email\":\"student@example.com\",\"purpose\":\"REGISTER\"}'

# 3. 注册（201）
curl.exe -i -X POST http://localhost:8080/api/v1/auth/register `
  -H "Content-Type: application/json" -H "Idempotency-Key: 8f31c2a0-9b7e-4d21-a6c5-0e2f1a3b4c5d" `
  -d '{\"username\":\"kaoyan_student\",\"email\":\"student@example.com\",\"verify_code\":\"482913\",\"password\":\"KaoYan@2026\",\"confirm_password\":\"KaoYan@2026\",\"nickname\":\"考研小白\",\"agree_agreement\":true}'

# 4. 账号密码登录（需要新取一次 captcha_key 并看图输入 4 位码）
curl.exe -s -X POST http://localhost:8080/api/v1/auth/login `
  -H "Content-Type: application/json" `
  -d '{\"login_type\":\"PASSWORD\",\"account\":\"kaoyan_student\",\"password\":\"KaoYan@2026\",\"captcha_key\":\"cap_xxx\",\"captcha_code\":\"7K9p\"}'

# 5. 当前用户 / 退出
curl.exe -s http://localhost:8080/api/v1/auth/me -H "Authorization: Bearer <token>"
curl.exe -s -X POST http://localhost:8080/api/v1/auth/logout -H "Authorization: Bearer <token>"

# 6. 重置密码后旧 Token 应返回 401 + 10001
curl.exe -s -X POST http://localhost:8080/api/v1/auth/password-reset `
  -H "Content-Type: application/json" -H "Idempotency-Key: 2b2b2b2b-1111-2222-3333-444455556666" `
  -d '{\"email\":\"student@example.com\",\"verify_code\":\"482913\",\"new_password\":\"NewKaoYan@2027\",\"confirm_password\":\"NewKaoYan@2027\"}'
curl.exe -i http://localhost:8080/api/v1/auth/me -H "Authorization: Bearer <旧token>"
```

锁定的验证：连续 5 次输错密码（每次都要重新取图形验证码），第 6 次应返回 **423 + 10003 + `Retry-After`**。

## 10. 遗留问题与风险

1. **禁用账号的错误码待确认**：接口文档 2.1 没有「账号禁用」专属码，当前用 **403 + 10008 + 「账号已被禁用，请联系管理员」**。
   建议 P2 在统一 401/403 时确认，或由接口文档补一个 `10013「账号已被禁用」`。
2. **邮箱唯一性只靠应用层查重**：`sys_user.email` 没有唯一索引。并发注册同一邮箱可能双写。
   建议数据库成员新增 `V7__unique_user_email.sql`：`ALTER TABLE sys_user ADD UNIQUE KEY uk_user_email (email);`
   （V1-V6 已冻结，不能直接改；代码侧已对唯一键冲突兜底成 409 + 10004。）
3. **旧 `/api/auth/*` 已移除**：前端现存登录页仍调用 `/api/auth/login`，由 P3 切到 `/api/v1/auth/*`；
   合并到 `feat/auth-foundation` 前请确认 P3 已改完，避免联调期前端登录 404。
4. **幂等记录暂无定时清理**：记录带 `expires_at`（24 小时），但没有清理任务。数据量小，后续可加一个删除过期记录的计划任务。
5. **`/api/kb/**` 仍是匿名白名单**（原仓库遗留）：属 P2 任务 7「保护现有接口」范围，P1 未改动以免影响其他人。
6. **README 的旧描述**：`backend/README.md` 里「谁先注册谁是管理员」「`/api/auth/*`」已过时，建议在集成分支统一更新（本分支只改了代码与配置）。
