# 数字大屏（甲）：后端统计接口实施手册

> 前置条件：管理员后台壳层已完成，存在可登录的管理员。
> 目标：提供一个大屏聚合接口，使用真实 MySQL 业务数据，避免前端首屏多次请求。
> 人员定位：后端数据统计负责人。

## 1. 交付范围

负责：

- 大屏 DTO。
- 用户、登录、文件、文档、聊天统计。
- 7/14/30 天趋势。
- 缺失日期补 0。
- Controller 权限和接口契约。
- Mapper 聚合 SQL。
- 必要索引迁移。
- Service 单元测试与 MockMvc 契约测试。

不负责：

- 前端页面。
- Redis 缓存。
- RabbitMQ 队列指标。
- 浏览器验收。

## 2. 接口定义

```http
GET /api/v1/admin/dashboard/summary?days=7
```

权限码：

```text
admin:user:list
```

`days` 只允许：

```text
7 / 14 / 30
```

响应：

```json
{
  "cards": {
```

- 时间统一使用 `Asia/Shanghai`。

## 4. 步骤 C1：创建 DTO

### 卡片 DTO

字段：

```text
totalUsers
enabledUsers
todayLogins
todayLoginFailures
files
storageBytes
documents
failedDocuments
conversations
chatMessages
todayChatMessages
```

所有计数使用 `Long`，字节数使用 `Long`。

### 趋势 DTO

```text
dates: List<String>
logins: List<Long>
uploads: List<Long>
chatMessages: List<Long>
```

四条数组长度必须完全一致。

### 系统 DTO

```text
mysql
redis
rabbitmq
docParseReady
docParseConsumers
docParseDlq
outboxPending
outboxFailed
```

前三个使用 `UP / DOWN`，其余使用非负整数。

## 5. 步骤 C2：用户和登录统计

### 总量

```sql
SELECT COUNT(*) FROM sys_user WHERE deleted = 0;
SELECT COUNT(*) FROM sys_user WHERE deleted = 0 AND status = 1;
```

如果表中没有 `deleted` 字段，以实际 schema 为准，不照抄 SQL。

### 今日登录

统计：

- 今日成功登录数。
- 今日失败登录数。

来源：

```text
sys_login_log
```

查询范围：

```text
[今天 00:00 Asia/Shanghai, 明天 00:00 Asia/Shanghai)
```

不要用 `DATE(create_time) = CURRENT_DATE()`，它会阻碍索引。

## 6. 步骤 C3：文件和文档

文件：

```text
COUNT(*) WHERE deleted = 0
COALESCE(SUM(file_size), 0) WHERE deleted = 0
```

今日上传：

```text
create_time >= 今日开始
create_time < 明日开始
```

知识库和文档：

- 统计知识库总数。
- 统计文档总数。
- 统计 `status = 'FAILED'` 的文档。

所有逻辑删除表都加 `deleted = 0`。

## 7. 步骤 C4：聊天统计

统计：

- 会话总数。
- 消息总数。
- 今日消息数。
- 最近 N 天消息趋势。

只查询 `COUNT` 和时间分组，不把 `content` 读入内存。

当前聊天前端尚未完成时，真实结果为 0 是合法结果，不能编造数据。

## 8. 步骤 C5：趋势 SQL 和日期补零

数据库只返回有数据的日期：

```text
date: 11-19, count: 12
date: 11-21, count: 18
```

Java 端生成完整日期：

```java
List<LocalDate> dates = IntStream.range(0, days)
    .mapToObj(offset -> today.minusDays(days - 1L - offset))
    .toList();
```

缺失日期补 `0L`。

趋势分为：

- 登录趋势：统计成功登录或全部登录，口径必须在 DTO 注释写清。建议统计成功登录。
- 上传趋势：以文件对象 `create_time` 为准。
- 聊天趋势：以 `chat_message.create_time` 为准。

## 9. 步骤 C6：聚合 Service

`DashboardStatisticsService` 一次组装：

1. Cards。
2. Trend。
3. 从可观测服务获取 System。
4. `generatedAt`。

建议定义接口，方便缓存和测试：

```java
public interface DashboardSummaryProvider {
    AdminDashboardSummaryVO build(int days);
}
```

系统指标服务由负责可观测性的同事提供。接口未落地前使用空实现，但不能返回假 UP。

## 10. 步骤 C7：Controller

新增：

```java
@RestController
@RequestMapping("/api/v1/admin/dashboard")
public class AdminDashboardController {
    @SaCheckPermission("admin:user:list")
    @GetMapping("/summary")
    public R<AdminDashboardSummaryVO> summary(
        @RequestParam(defaultValue = "7") int days
    ) {
        return R.ok(service.summary(days));
    }
}
```

`days` 不是 7、14、30 时返回 400。

## 11. 步骤 C8：索引检查

逐项检查实际 SQL 的 `EXPLAIN`：

- `sys_login_log(create_time, success)`
- `file_object(owner_user_id, create_time, deleted)`
- `chat_message(conversation_id, create_time)`
- `kb_document(status, create_time)`
- `sys_message_outbox(status, next_retry_at)`

索引不足时新增 `V11__dashboard_metrics_indexes.sql`，禁止修改已存在迁移。

## 12. 步骤 C9：测试

### Service 单元测试

- 空库所有计数为 0。
- 今日边界使用 Asia/Shanghai。
- 7/14/30 天数组长度正确。
- 缺失日期补 0。
- `SUM(file_size)` 为 null 时返回 0。
- 失败文档计数正确。

### MockMvc 契约测试

- 学生 Token 403 + 10008。
- `DATA_AUDITOR` 200。
- 管理员 200。
- `days=8` 400。
- JSON 字段名与前端契约一致。
- 响应不含敏感字段。
