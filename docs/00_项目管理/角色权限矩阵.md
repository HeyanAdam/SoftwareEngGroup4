## 1. 命名规则（与接口文档一致）

| 项 | 规则 |
|---|---|
| 格式 | `module:action` |
| `module` | 与接口路径的资源名一致：`/api/v1/study-plans` → `study-plan`，`/api/v1/knowledge-bases` → `kb` |
| `action` | `view` / `create` / `update` / `delete` / `upload` / `download` / `send` / `manage` |
| 示例 | `study-plan:view`、`file:upload`、`admin:user:list` |
| 兼容性 | main 分支 V6 已上线的 11 条权限码**一个都不改**，新增权限码按本规则追加 |

> 为什么不用 docx 里的 `studyplan:add`：本项目接口路径是 `study-plans`（带中划线、复数），权限码跟着路径走才能在代码里一一对上；
> 且 main 分支已经落库了 11 条 `kb:view` 这类写法，改名会和已合并的 V6 冲突。

**数据范围说明**

- `ALL`：可读全部数据（管理员、内容运营）。
- `SELF`：仅本人数据，访问他人资源返回 403 + `10009`。
- `MASKED`：可看列表与汇总，敏感字段脱敏（邮箱 `stu***@example.com`），不得看明细。

> 学生为什么不给 `kb:view`：接口文档 11.5 规定普通学生不得直接浏览知识库原文、切片与向量，只能通过 AI 对话间接使用。
> `STUDENT` 的 ◇ 建议授权只涉及学习计划、题库、本人文件，不涉及知识库。

## 5. 需要数据库同学补的 V7 迁移（草案）

main 分支规矩：**已合并的 V6 不得修改，只能新增版本**。V7 内容就是上表「待新增」的 9 条权限码 + 授权。

```sql
-- V7__extend_rbac_business_permissions.sql
-- 仅新增 9 条业务权限码，不改 V6 既有 11 条，不改任何已上线角色的既有授权。

INSERT INTO sys_permission (perm_code, perm_name, perm_type, parent_id, path, sort)
VALUES
  ('study-plan:view',   '查看学习计划', 'API', 0, NULL, 120),
  ('study-plan:create', '生成学习计划', 'API', 0, NULL, 130),
  ('study-plan:update', '调整学习计划', 'API', 0, NULL, 140),
  ('study-task:update', '更新任务状态', 'API', 0, NULL, 150),
  ('question:view',     '浏览题库',     'API', 0, NULL, 160),
  ('file:view',         '文件列表',     'API', 0, NULL, 170),
  ('file:upload',       '上传文件',     'API', 0, NULL, 180),
  ('file:download',     '下载文件',     'API', 0, NULL, 190),
  ('file:delete',       '删除文件',     'API', 0, NULL, 200)
AS seed
ON DUPLICATE KEY UPDATE
  perm_name = seed.perm_name, perm_type = seed.perm_type,
  parent_id = seed.parent_id, path = seed.path, sort = seed.sort;

-- SYSTEM_ADMIN 自动获得全部权限（含新增）
INSERT IGNORE INTO sys_role_permission (role_id, permission_id)
SELECT r.id, p.id FROM sys_role r JOIN sys_permission p
WHERE r.role_code = 'SYSTEM_ADMIN';
```
