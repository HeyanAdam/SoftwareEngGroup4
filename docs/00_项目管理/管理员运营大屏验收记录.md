## 2. 实现细节与口径

### 2.1 Redis 缓存（E1）

- Key：`admin:dashboard:summary:v1:{days}`，`days` 独立成 key，7/14/30 切换互不串数据。
- TTL：固定 15 秒，与前端轮询同频；不写永久 key。
- Value：`AdminDashboardSummaryVO` 的 JSON，只含计数与状态字符串。
- 降级：读、反序列化、写任一环节异常只记 `warn`，按未命中处理，照常返回真实统计。
- 安全：不使用 `KEYS *`；缓存不含聊天正文、邮箱、对象存储 key 或任何凭据。

### 2.2 队列指标（E2）

| 字段 | 来源 | 口径 |
|---|---|---|
| `docParseReady` | `kaoyan.doc.parse.queue` | `QueueInformation#getMessageCount()` 就绪消息数 |
| `docParseConsumers` | 同上 | `QueueInformation#getConsumerCount()` 在线消费者数 |
| `docParseDlq` | `kaoyan.doc.parse.dlq` | 死信消息数 |

- 只走服务端 `RabbitAdmin#getQueueInfo`，前端不接触 RabbitMQ 管理端口。
- 队列不存在 / `RabbitAdmin` 未装配 / AMQP 异常 → `up=false`、三项归 0，上层把 `rabbitmq` 置 `DOWN`。
- 日志只写异常摘要，不打印 broker 账号密码。

### 2.3 Outbox 指标（E3）

```
outboxPending = PENDING + RETRY_WAIT           （正常排队，待投递）
outboxFailed  = FAILED + PUBLISHING 超过 5 分钟  （失败 + 实例崩溃遗留的孤儿记录）
```

- 5 分钟阈值与 `OutboxPublisherJob` 的 `resetStuck(now - 5m)` 同源。
- `OutboxMapper` 新增两条 COUNT 查询：`countByStatus(status)`、`countStuckPublishing(staleBefore)`；
  不 `SELECT payload_json`，大屏拿不到消息正文。

### 2.4 系统健康指标（E4）

- 三项并行、各自独立：MySQL `Connection#isValid`、Redis `PING`、RabbitMQ `createConnection#isOpen`。
- 单项上限 2 秒，超时取消任务并判 `DOWN`；一项 DOWN 不影响其他两项。
- `HealthController` 的 `/ready` 已改为复用该服务，Controller 不再重复拼三份探活逻辑。

### 2.5 集成（E5）

```
校验 days(7/14/30) → 读缓存 → DashboardSummaryProvider#buildBusiness → 探活/队列/Outbox → 组装 DTO → 写缓存
```

- `DashboardSummaryProvider` 契约：`AdminDashboardSummaryVO buildBusiness(int days)`，只负责 `cards` 与 `trend`。
- 甲的实现未合并时：Provider 缺失 → 全 0 的合法空结果、日期仍连续补 0；**不编造数据、不返回假 UP**。
- `generatedAt` 统一 `Asia/Shanghai` 的 ISO 8601（如 `2026-11-22T10:00:00+08:00`）。
- 接口 `produces = application/json`，避免 XML 内容协商把契约带偏。

### 2.6 降级矩阵

| 故障 | 接口结果 |
|---|---|
| Redis 不可用 | 跳过缓存直接统计，`redis=DOWN`，页面正常 |
| RabbitMQ 不可用 | `rabbitmq=DOWN`、队列数字归 0，业务 KPI 正常 |
| Outbox 表查询失败 | `outboxPending/outboxFailed=0`，其余不变 |
| MySQL 探活失败 | `mysql=DOWN`，业务统计若同时失败才向上抛错 |
| 单项探活超时 | 该项 `DOWN`，其余两项照常返回 |

## 3. 接口与权限

```http
GET /api/v1/admin/dashboard/summary?days=7|14|30
```

- 权限码：`admin:user:list`（与甲的分册一致：`DATA_AUDITOR` 可读、学生 403 + 10008）。
- `days` 非 7/14/30 → HTTP 400 + `code=10000`。
- 未登录 → 401 + 10001（由 `WebConfig` 的 Sa-Token 拦截器统一处理）。

## 5. 真实环境验收步骤（待执行为勾选项）

前置：

```powershell
cd deploy
docker compose ps
Invoke-RestMethod http://localhost:8080/api/v1/health/ready
docker exec kaoyan-rabbitmq rabbitmqctl -q list_queues name messages_ready messages_unacknowledged consumers
```

管理员登录后逐项确认：

- [ ] `/admin/dashboard` KPI 与 SQL 查询一致
- [ ] 队列数字与 `rabbitmqctl list_queues` 一致
- [ ] `docker stop kaoyan-redis` → Redis 状态红、业务数据照常、无无限 loading
- [ ] `docker start kaoyan-redis` → 下一轮轮询自动恢复
- [ ] `docker stop kaoyan-rabbitmq` → RabbitMQ 状态红、用户/文件/聊天统计仍展示
- [ ] 恢复 RabbitMQ 后状态回绿
- [ ] 15 秒轮询、页面隐藏暂停、全屏、手动刷新
- [ ] 未登录访问 → 401 + 10001
- [ ] 学生访问 → 403 + 10008
- [ ] `DATA_AUDITOR` → 200 只读可用
- [ ] `SYSTEM_ADMIN` → 200
- [ ] 前端直接输入 `/admin/dashboard` 无后台会话 → 跳 `/admin/login`
- [ ] 冷启动聚合 < 1s；Redis 命中 < 200ms；连续刷新 10 次无慢查询增长
- [ ] `EXPLAIN` 无全表扫描；SQL 无 `SELECT *`

采集命令示例：

```powershell
# 未登录
Invoke-WebRequest http://localhost:8080/api/v1/admin/dashboard/summary?days=7

# 学生 Token（403 + 10008）
Invoke-RestMethod "http://localhost:8080/api/v1/admin/dashboard/summary?days=7" `
  -Headers @{ Authorization = "Bearer <student-token>" }

# Redis key 与 TTL
docker exec kaoyan-redis redis-cli --scan --pattern "admin:dashboard:summary:v1:*"
docker exec kaoyan-redis redis-cli TTL admin:dashboard:summary:v1:7
```

## 7. 遗留与风险

1. 真实环境验收未执行：本机无 Docker 与运行中的中间件，E7/E8/E9 需在具备 `deploy/docker-compose.yml` 的机器上补做并回填截图。
2. 业务统计缺失：Provider 未接入时大屏 KPI 全 0 属预期，不是线上故障。
3. 缓存 15 秒内数据有轻微滞后：与轮询同频，验收时以轮询后的稳定值为准。
4. 若后续新增 `days` 取值，需同步改 `ALLOWED_DAYS`、前端类型与缓存 key 文档。
