## 2. 当前登录用户 ID

- 登录时 `StpUtil.login(user.getId())`，**loginId 是 `sys_user.id`（Long），不是用户名、不是 UUID**。
- 取当前用户统一用：

```java
Long userId = StpUtil.getLoginIdAsLong();
```

- 你已有的 `StpInterfaceImpl` 里「loginId 非数字返回空权限」的处理与此一致，**不要改回字符串解析**。
- 未登录时抛出 `NotLoginException`，已由全局异常处理转成 `401 + 10001`，你不用自己 catch。

---

## 3. 角色与权限：不要自己查库，用同一份快照

登录、`/me`、`@SaCheckPermission` 校验三者**必须同源**，否则会出现「前端显示有权限、后端 403」。我这边已经全部改走你的缓存：

```java
RbacSnapshotCache.Snapshot snapshot = rbacSnapshotCache.get(userId);
List<String> roles = snapshot.roles();        // 如 ["STUDENT"]
List<String> permissions = snapshot.permissions(); // 如 ["chat:send"]
```

- `/api/v1/auth/login` 与 `/api/v1/auth/me` 的 `roles` / `permissions` 就来自这里，**不直接读 `RoleMapper` / `PermissionMapper`**。
- 你新增授权、改角色后必须清缓存：`evict(userId)` / `evictByRoleId(roleId)`，`AdminService` 里已有调用，新增的管理接口请照做。
- 新用户注册成功后我会 `evict` 一次，避免他第一次 `/me` 拿到空权限。

## 4. 会话吊销：三件套

```java
sessionService.logoutCurrentSession();      // 退出登录，只吊销当前 Token
sessionService.logoutUser(Long userId);     // 强制下线：吊销该用户全部 Token
sessionService.isUserLoggedIn(Long userId); // 是否还有有效会话
```

使用约定：

| 场景 | 调用 |
|---|---|
| `/auth/logout` | 已由我调用 `logoutCurrentSession()` |
| 重置密码 | 已由我调用 `logoutUser(userId)`，保证旧 Token 立即失效 |
| **管理员禁用用户**（你的任务 3） | **请你调用 `logoutUser(userId)`**，并把 `sys_user.status` 置禁用 |
| 管理员改角色 / 改权限 | 不需要踢下线，但要 `evict` 快照缓存 |

原因：Sa-Token 配置是 `is-concurrent: true, is-share: false`，一个账号可能有多个 Token，`StpUtil.logout()` 只杀当前一个，所以「强制下线」必须走 `logoutUser`。

## 5. 认证错误码全表（前端和 P3 都按这张表）

| code | HTTP | 含义 | 触发场景 | 归属 |
|---|---|---|---|---|
| 10000 | 400 | 参数校验失败 | 字段为空/格式错/JSON 非法/缺 `Idempotency-Key` | P1 |
| 10001 | 401 | 未登录或登录已失效 | 无 Token、Token 过期、被吊销 | P1（全局） |
| 10002 | 401 | 账号或密码错误 | 账号不存在与密码错**统一**返回，防枚举 | P1 |
| 10003 | 423 + `Retry-After` | 账号已锁定 | 连续失败 5 次，锁 15 分钟 | P1 |
| 10004 | 409 | 账号或邮箱已存在 | 注册时用户名/邮箱冲突 | P1 |
| 10005 | 400 | 验证码错误/过期/超次 | 图形码错 3 次作废；邮箱码错 5 次作废 | P1 |
| 10006 | 400 | 两次密码不一致 | 注册、重置密码 | P1 |
| 10007 | 404 | 用户不存在 | 邮箱验证码登录时邮箱未注册 | P1 |
| 10008 | 403 | 无接口访问权限 | `@SaCheckPermission` 不通过 | **P2** |
| 10009 | 403 | 无权访问该数据 | 数据范围越权（SELF 访问他人资源） | **P2** |
| 10010 | 429 + `Retry-After` | 操作过于频繁 | 认证接口限流 | P1 |
| 10011 | 409 | 幂等键对应请求处理中 | 同一 `Idempotency-Key` 并发提交 | P1 |
| 10012 | 400 | 请求类型不受支持 | 方法不对（如 GET 打 POST 接口） | P1 |
| 10013 | 403 | **账号已被禁用** | 密码登录/邮箱登录时 `sys_user.status=0` | P1 自定，**待文档确认** |
| 90000 | 500 / 503 | 服务器内部异常 | 兜底；邮件服务不可用时 503 | P1 |

注意两点：

1. **10008 与 10009 是给你的**，P1 只在 `AuthErrorCode` 里登记了常量，没有业务使用；`DataScope` 越权请抛 `10009`，不要复用 10008。
2. **10013 是我在文档缺项的情况下自取的码**（接口文档 2.1 只到 10012）。如果你认为应该复用别的码，请提出来，改动只涉及 `AuthErrorCode.ACCOUNT_DISABLED` 和 `AuthException.disabled()` 一处。

## 7. Redis Key 命名（auth 归我，其余归你）

| Key | TTL | 用途 |
|---|---|---|
| `auth:captcha:{captcha_key}` | 5 分钟 | 图形验证码答案 |
| `auth:captcha:fail:{captcha_key}` | 5 分钟 | 图形码错误计数（3 次作废） |
| `auth:code:{PURPOSE}:{email}` | 5 分钟 | 邮箱验证码本体 |
| `auth:code:send:email:{PURPOSE}:{email}` | 60 秒 | 同邮箱重发间隔 |
| `auth:code:send:ip:{ip}` | 60 秒 | 同 IP 重发间隔 |
| `auth:code:fail:{PURPOSE}:{email}` | 5 分钟 | 邮箱码错误计数（5 次作废） |
| `auth:login:fail:{account}` | 30 分钟 | 登录失败计数 |
| `auth:login:lock:{account}` | 15 分钟 | 锁定标记 |
| `auth:login:fail:ip:{ip}` | 30 分钟 | IP 维度失败计数 |
| `auth:rate:{action}:{identity}` | 按动作 | 接口限流计数 |

`PURPOSE` ∈ `REGISTER` / `EMAIL_LOGIN` / `RESET_PASSWORD`。

**请你的缓存用独立的 key 前缀**（如 `rbac:snapshot:{userId}`），不要落到 `auth:` 下，便于按前缀排查；如果已经用了别的命名，回我一句，我写进文档即可。

## 11. 自测路径（验证你的 RBAC 与我的认证能串起来）

```bash
# 1) 注册，拿到 token（必须带 Idempotency-Key）
curl -i -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" -H "Idempotency-Key: $(uuidgen)" \
  -d '{"username":"stu_01","email":"stu01@example.com","verify_code":"482913","password":"KaoYan@2026","confirm_password":"KaoYan@2026","nickname":"考研小白","agree_agreement":true}'

# 2) /me 看角色权限（应为 STUDENT + chat:send）
curl -H "Authorization: Bearer <token>" http://localhost:8080/api/v1/auth/me

# 3) 用学生 token 打管理接口，应 403 + 10008
curl -i -H "Authorization: Bearer <token>" http://localhost:8080/api/v1/admin/users
```

第 3 步的 403 + 10008 就是你我这条链路的验收点。
