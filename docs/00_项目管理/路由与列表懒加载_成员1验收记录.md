## 二、列表数据懒加载

### 2.1 既有分页复核

文件列表、管理员用户/日志等既有分页未改动，仍为「单页 + 总数」模式。

### 2.2 聊天历史接口（后端）

`GET /api/v1/chat/conversations/{id}/messages`

| 参数 | 说明 |
|---|---|
| `before_id` | 可选。返回 ID 严格小于该值的更早消息；不传表示最近一页 |
| `limit` | 可选。默认 20，上限 100，小于 1 时回退默认值 |

- **兼容**：两个参数都不传时保持旧行为，直接返回消息数组（升序），既有调用不受影响。
- **分页**：传了任一参数时返回 `{ items, has_more, next_before_id }`：
  - 后端按 ID 倒序 **多查一条**（`limit + 1`）判断 `has_more`；
  - 返回前恢复为时间升序；
  - `next_before_id` 为当前页最早一条的 ID，无更早消息时为 `null`。
- 归属校验沿用原逻辑（越权 403、不存在 404）。

示例：

```http
GET /api/v1/chat/conversations/12/messages?before_id=100&limit=20
→ {"code":0,"data":{"items":[...],"has_more":true,"next_before_id":81}}
```

实现位置：`ChatController#messages`、`ChatService#messagePage`、`ChatHistoryPage`。

### 2.3 聊天历史加载（前端）

- **首屏**：`selectConversation` 只请求最近一页（`limit=20`，不带 `before_id`）。
- **加载更早**：Store 新增 `hasMoreMessages / loadingEarlier / earlierError / nextBeforeId / messageLoadToken`，
  `loadEarlierMessages()` 以 `nextBeforeId` 为游标向前翻页。
- **去重**：按服务端消息 ID 合并，重复消息丢弃（[chat.history.ts](../../frontend/src/features/chat/chat.history.ts)）。
- **竞态**：切换会话时 `messageLoadToken` 自增，旧会话慢响应直接丢弃；加载中重复点击不会重复请求。
- **页面交互**：消息区顶部提供「加载更早消息」按钮、加载中文案、失败重试按钮、没有更多提示；
  滚动到距顶部 48px 内自动加载。
- **位置稳定**：加载前记录容器 `scrollHeight/scrollTop`，插入后用
  `scrollTop + (newHeight - oldHeight)` 修正，用户正在阅读的消息不跳动；自动滚动只跟随末尾消息，不再因前置插入跳到最底部。

## 四、手工验收步骤（需本地起服务）

1. `cd frontend; npm run dev`，登录后打开 DevTools → Network，筛选 `messages`。
2. 打开一个有较多历史的会话：应只出现 1 条 `messages?limit=20` 请求（无 `before_id`）。
3. 点击「加载更早消息」或滚动到顶部：出现 `messages?before_id=<next_before_id>&limit=20`，列表顺序正确、无重复。
4. 连续加载到 `has_more=false`：继续滚动不再发请求，顶部显示「没有更早的消息了」。
5. 加载过程中切换会话：旧请求返回后当前列表不变化。
6. 首屏验收：登录页 Network 中只加载 `LoginPage-*.js`，进入 `/chat` 后才加载 `ChatPage-*.js`，进入后台才加载 `Admin*Page-*.js`。

## 五、已知边界

- 本机 `mvn -o -Dtest="*Chat*Test" test` 中，既有聊天用例（`ChatStreamServiceTest` 等）因 JDK 24 + Byte Buddy 版本不兼容报错，属于环境问题、与本次改动无关；本次新增的 `ChatServiceTest` 在该环境下 5 项全部通过。
- 不传分页参数时旧接口仍返回全量数组，属于兼容口径；新代码统一走分页参数。
- `has_more` 基于 `limit + 1` 探测，翻页期间若有新消息写入，只影响「更新的一侧」，更早历史游标不受影响。
- 自动刷新仅针对动态导入失败，其他路由错误保持原有行为。
